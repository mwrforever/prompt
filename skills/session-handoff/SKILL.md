# Session Handoff（会话交接）

> 职责：把当前会话的任务进度固化为一篇脱离对话历史即可独立续接的**任务交接文档**，落盘于 `<目标项目根>/docs/progress/{yyyy-mm-dd}-{精简标题}.md`。
> 本技能**只做进度文档的生成与更新，不做任何任务实现**；并且是会话的**终止动作**而非"保存"动作：文档生成并回报后，当前会话的任务实现就此封存，未完成部分移交【新会话】继续。

## 一、触发与加载（仅限手动）

- **唯一入口是用户的手动调用**：用户主动说出「保存进度 / 交接 / 生成交接文档 / 保存会话进度 / 记录进度 / 续接准备 / 收尾交接」等明确意图，或显式输入 `/session-handoff [update|rewrite] {用户指令}` 时，执行本技能。
- **触发后必须先加载本技能**：读取本 SKILL.md 与 `references/handoff-template.md`，严格按本技能流程执行；禁止跳过技能内容、仅凭对话印象直接写文档。
- **禁止主动或自动触发**：不得自行发起；不得在会话自然收尾、任务完成或即将结束时自动询问"是否需要保存进度"；不得在用户未明确要求时生成任何文档。
  本技能不存在被动触发路径，唯一入口是用户的手动调用。

## 二、行为红线：只生成文档，不实现任务

触发本技能后，**唯一允许的动作是生成或更新交接文档**：

1. 用户指令中夹带的任何实现诉求（如「保存进度，顺便把 X 修了」「先把 Y 跑通再交接」）一律**拒绝实现**，只生成交接文档；该诉求本身作为未完成事项如实写入文档。
2. 生成过程中发现的问题（代码缺陷、测试失败、遗漏步骤）只**如实记录**进文档，不得顺手修复，也不得为写文档而继续展开调研或验证。
3. 文档生成（或更新）完毕并回报用户后，立即进入第七节的封存状态。

## 三、子命令路由

调用格式：`/session-handoff [子命令] {用户指令}`，按子命令在「更新」与「新建」之间路由：

| 调用方式 | 行为 |
| --- | --- |
| `/session-handoff {用户指令}` 或 `/session-handoff rewrite {用户指令}` | **默认，rewrite：新建**一篇交接文档 |
| `/session-handoff update {用户指令}` | **update：原地更新**本会话已生成的那篇交接文档，不新建文件 |

- **rewrite（默认）**：每次新建一篇文档，禁止覆盖既有文档；用于本会话首次交接，或用户明确要求重新生成一份。
- **update**：更新对象是**当前会话内引入的进度文件**——即本会话通过本技能生成的交接文档，或本会话开始续接时读取的、符合 `<项目根>/docs/progress/{yyyy-mm-dd}-{精简标题}.md` 目录规范的那篇文档；**绝不是从用户历史记忆、历史会话中检索出来的旧文档**。用于文档生成或续接后用户补充进展、修正内容。当前项目没有会话内引入的、符合目录规范的进度文件时，update 直接退化为默认 rewrite 新建一篇，并向用户说明。

## 四、内容来源约束（引用红线，rewrite 与 update 均须遵守）

文档中写入的每一条内容，**唯一合法来源是当前会话中发生的设计、实现与产物事实**：

1. **只写当前会话相关内容**：只记录本次会话涉及的设计决策、代码实现、验证结果与产物状态；超出本次会话范围的内容（项目里其他模块、其他任务、用户顺带提及的背景）一律不写入。
2. **禁止叠加引用上一份进度文档**：本文档必须自包含。不得出现「承接 / 参见 / 续接上一份交接文档 `docs/progress/xxx.md`」之类的跨文档引用，也不得把旧文档的内容搬运拼接进本文档；确需背景时，把必要事实**直接写明**在本文档里。
3. **禁止基于历史记忆引用旧文档**：不得检索用户记忆系统、历史会话记录，引用此前的交接文档来填充内容。update 的对象也只认当前会话内引入的那篇进度文件，不认任何从记忆中翻出的历史文档。
4. **精确、完整、不冗余**：
   - 精确：路径、命令、状态、结论必须来自当前会话的真实操作与产物，查证不到的不写；
   - 完整：新会话仅凭本文档即可续接，不留信息缺口；
   - 不冗余：不堆砌与续接无关的细节，已完成部分只留一句话结论。

## 五、rewrite 流程（默认，新建文档）

1. **确定存放目录**：交接文档必须放在任务所属项目的**真实根目录**下的 `docs/progress/` 子目录，不要放在对话工具的临时会话目录（通常是以时间戳自动生成的临时工作目录），否则下次续接时找不到。若当前工作目录就是项目目录可直接用；不确定时向用户确认项目绝对路径。若 `docs/progress/` 目录不存在，先创建它再写入文件。
2. **确定文件名**：格式 `<项目根>/docs/progress/{yyyy-mm-dd}-{精简标题}.md`。
   - `yyyy-mm-dd`：保存当天的日期（如 2026-08-24）。
   - `精简标题`：**不超过 15 个汉字**，概括本次任务（如"待办工具cli实现"）。任务描述模糊时先向用户确认一个简短标题再写入。
   - 当天同名文档已存在时追加序号后缀 `-2`、`-3`（如 `2026-08-24-待办工具cli实现-2.md`），保留完整交接历史，禁止覆盖。
3. **读取模板** `references/handoff-template.md`，严格按结构填写，模板顶部的「交接声明」必须原样保留。
4. **第 1 节 已完成**：只做简要标记，逐条列出本次会话已做完的事项及一句话结果，不展开。它的唯一作用是告诉新会话"这些不用再做"。
5. **第 2 节 未完成（重点详述）**：对每一个未完成的任务，用模板的子结构填写，必须包含：目标（可验证的最终结果）、当前状态（具体到文件/产物/已通过的环节）、涉及文件/产物（绝对路径或标识 + [新建]/[修改]/[待创建]）、已锁定决策（新会话不得推翻）、阻塞点/风险、**下一步具体动作**（可立即执行的最小下一步，写明命令/位置/操作，禁止写"继续做"这类空话）、验证方式。这是续接能否成功的关键，宁可写细，不要省略。
6. **第 3 节 环境与依赖**：记录运行时版本、关键配置、安装/构建/启动命令（若适用），确保新会话能复现环境。
7. **第 4 节 全局约定**：记录跨会话必须遵守的目录结构、命名、接口契约、用户硬性约束。
8. **元信息**：填 `workspace_dir`（真实项目绝对路径）、`saved_at`（ISO8601 当前时间）、`生成方式`（rewrite）、`版本控制提交号`（当前提交号，如 git 的 commit hash；不使用版本控制则填 N/A）、`交接状态`（待新会话续接）、任务一句话描述。
9. **回报用户（交接宣言）**：告知交接文档的绝对路径，附一句话总结（已完成几项 / 待续几项 / 从哪一步开始），并明确宣布：
   "本会话的任务已交接封存。请在【新会话】中打开 `<项目根>`，读取 `docs/progress/` 下最新的交接文档继续执行。"
   宣布完成后，立即进入第七节的封存状态，不再执行任何任务实现。

## 六、update 流程（更新本会话已生成的文档）

1. **定位更新对象**：更新对象只能是**当前会话内引入的进度文件**——本会话通过本技能生成的交接文档，或本会话开始续接时读取的那篇符合 `<项目根>/docs/progress/{yyyy-mm-dd}-{精简标题}.md` 目录规范的文档。禁止从用户历史记忆、历史会话记录中检索旧文档作为更新对象。当前项目不存在这样的文件时，转按第五节 rewrite 新建一篇，并向用户说明。
2. **只合并当前会话的新事实**：把用户指令中的新进展、修正、补充决策并入对应章节；合并内容同样受第四节约束，不得为省事引用旧文档或上一份进度文档。
3. **原地重写受影响章节**：新事实写入后，同步改写或删除已过时的条目（已完成事项移入第 1 节、矛盾状态以最新为准），保持文档自包含、无冗余、结构与模板一致。
4. **刷新元信息**：更新 `saved_at` 与版本控制提交号，`生成方式` 改为 update；文件名与路径不变，不新建文件。
5. **回报用户**：告知更新了哪些章节，并重申第七节的封存状态（update 只维护文档，不解除封存）。

## 七、触发即封存（当前会话的行为约束，必须遵守）

交接文档生成（或 update 更新完毕）并向用户回报后，当前会话立即封存任务、不再进行任何任务实现：

1. **停止一切任务实现**：不得继续编写/修改代码、不得推进未完成步骤、不得"顺手"完成交接文档中记录的待办事项，也不得继续调研或验证。update 子命令只允许修改交接文档本身，不得借更新之机实现任务。
2. **拒绝已交接任务的续做请求**：若用户在交接完成后继续提出与已交接任务相关的实现请求（如「继续做」「接着改 X」「把剩下的完成」），必须回答：
   "该任务已交接至新会话，请开启新会话并读取 `<交接文档绝对路径>` 后继续，本会话不再执行。"
   **不得在当前会话执行。**
3. **全新任务默认引导新会话**：交接后用户提出的全新实现任务，默认建议开新会话执行（本会话已完成交接封存，避免两处并行推进）；仅纯信息查询（解释文档内容、确认路径等，不涉及任务实现）可在当前会话直接回答。

## 八、设计要点（为何这样能保证交接）

- **自包含**：所有续接事实（状态、决策、下一步、验证）都在一份文档里，且只来自当前会话，不依赖对话历史、旧交接文档或用户记忆（新会话本就没有这些）。
- **显式交接声明**：文档顶部声明未完成部分须在新会话执行，杜绝"当前会话继续做"与"新会话重新发明"两处歧义。
- **已完成=结论、未完成=细节**：信息密度向"未做的下一步"倾斜，避免新会话在已完成处空转。
- **锁定决策 + 全局约定**：显式记录不可更改项，防止新会话"重新发明"或破坏已有结构。
- **rewrite 默认新建、update 原地修正**：新建保留完整交接历史，新会话永远读最新一篇；更新只服务本会话的文档修订，不产生跨文档叠加引用链。
- **版本控制提交号漂移检测**：新会话对比提交号即可发现环境变化并确认。
