# Session Handoff（会话交接）

> 职责：把当前会话的任务进度固化为一篇脱离对话历史即可独立续接的**任务交接文档**，落盘于 `<目标项目根>/docs/progress/{yyyy-mm-dd}-{精简标题}.md`。
> 本技能是会话的**终止动作**而非"保存"动作：一旦执行，当前会话的任务实现就此封存，未完成部分移交【新会话】继续。

## 一、何时使用（仅限手动触发）

- 当用户主动说出「保存进度 / 交接 / 生成交接文档 / 保存会话进度 / 记录进度 / 续接准备 / 收尾交接」等明确意图、要求生成交接文档时，执行本技能。
- **禁止主动或自动触发**：不得自行发起；不得在会话自然收尾、任务完成或即将结束时自动询问"是否需要保存进度"；不得在用户未明确要求时生成任何文档。
  本技能不存在被动触发路径，唯一入口是用户的手动调用。

## 二、触发即封存（当前会话的行为约束，必须遵守）

生成交接文档并向用户回报后，当前会话立即封存任务、不再进行任何任务实现：

1. **停止一切任务实现**：不得继续编写/修改代码、不得推进未完成步骤、不得"顺手"完成交接文档中记录的待办事项，也不得继续调研或验证。
2. **拒绝已交接任务的续做请求**：若用户在交接完成后继续提出与已交接任务相关的实现请求（如「继续做」「接着改 X」「把剩下的完成」），必须回答：
   "该任务已交接至新会话，请开启新会话并读取 `<交接文档绝对路径>` 后继续，本会话不再执行。"
   **不得在当前会话执行。**
3. **全新任务默认引导新会话**：交接后用户提出的全新实现任务，默认建议开新会话执行（本会话已完成交接封存，避免两处并行推进）；仅纯信息查询（解释文档内容、确认路径等，不涉及任务实现）可在当前会话直接回答。

## 三、使用方法

1. **确定存放目录与新建文档**：交接文档必须放在任务所属项目的**真实根目录**下的 `docs/progress/` 子目录，不要放在对话工具的临时会话目录（通常是以时间戳自动生成的临时工作目录），否则下次续接时找不到。若当前工作目录就是项目目录可直接用；不确定时向用户确认项目绝对路径。
   - 文件名格式：`<项目根>/docs/progress/{yyyy-mm-dd}-{精简标题}.md`
     - `yyyy-mm-dd`：保存当天的日期（如 2026-08-24）。
     - `精简标题`：**不超过 15 个汉字**，概括本次任务（如"待办工具cli实现"）。任务描述模糊时先向用户确认一个简短标题再写入。
   - **每次触发必须新建文档，禁止覆盖**：若当天同名文档已存在，追加序号后缀 `-2`、`-3`（如 `2026-08-24-待办工具cli实现-2.md`），保留完整交接历史；新会话永远读取最新一篇。
   - 若 `docs/progress/` 目录不存在，先创建它再写入文件。
2. **读取模板** `references/handoff-template.md`，严格按结构填写，模板顶部的「交接声明」必须原样保留。
3. **第 1 节 已完成**：只做简要标记，逐条列出本次会话已做完的事项及一句话结果，不展开。它的唯一作用是告诉新会话"这些不用再做"。
4. **第 2 节 未完成（重点详述）**：对每一个未完成的任务，用模板的子结构填写，必须包含：
   - 目标（可验证的最终结果）
   - 当前状态（具体到文件/产物/已通过的环节）
   - 涉及文件/产物（绝对路径或标识 + [新建]/[修改]/[待创建]）
   - 已锁定决策（新会话不得推翻）
   - 阻塞点/风险
   - **下一步具体动作**（可立即执行的最小下一步，写明命令/位置/操作，禁止写"继续做"这类空话）
   - 验证方式（如何确认这一步做对了）
   这是续接能否成功的关键，宁可写细，不要省略。
5. **第 3 节 环境与依赖**：记录运行时版本、关键配置、安装/构建/启动命令（若适用），确保新会话能复现环境。
6. **第 4 节 全局约定**：记录跨会话必须遵守的目录结构、命名、接口契约、用户硬性约束。
7. **元信息**：填 `workspace_dir`（真实项目绝对路径）、`saved_at`（ISO8601 当前时间）、`版本控制提交号`（版本控制系统当前提交号，如 git 的 commit hash；不使用版本控制则填 N/A）、`交接状态`（待新会话续接）、任务一句话描述。
8. **回报用户（交接宣言）**：告知交接文档的绝对路径，附一句话总结（已完成几项 / 待续几项 / 从哪一步开始），并明确宣布：
   "本会话的任务已交接封存。请在【新会话】中打开 `<项目根>`，读取 `docs/progress/` 下最新的交接文档继续执行。"
   宣布完成后，立即进入本技能第二节规定的封存状态，不再执行任何任务实现。

## 四、设计要点（为何这样能保证交接）

- **自包含**：所有续接事实（状态、决策、下一步、验证）都在一份文档里，不依赖对话历史（新会话本就没有历史）。
- **显式交接声明**：文档顶部声明未完成部分须在新会话执行，杜绝"当前会话继续做"与"新会话重新发明"两处歧义。
- **已完成=结论、未完成=细节**：信息密度向"未做的下一步"倾斜，避免新会话在已完成处空转。
- **锁定决策 + 全局约定**：显式记录不可更改项，防止新会话"重新发明"或破坏已有结构。
- **每次交接新建文档**：历史可回溯，新会话永远读最新一篇，不覆盖旧交接。
- **版本控制提交号漂移检测**：新会话对比提交号即可发现环境变化并确认。
