# Session Handoff（会话交接）

把当前会话的任务进度固化为一篇**自包含的交接文档**，落盘于 `<项目根>/docs/progress/{yyyy-mm-dd}-{精简标题}.md`，供【新会话】脱离对话历史独立续接。
本技能是会话的**终止动作**而非"保存"动作：文档回报后当前会话即封存，未完成部分移交【新会话】继续。

## 一、触发与加载（仅限手动）

- **唯一入口是用户手动调用**：用户明确说出「保存进度 / 交接 / 生成交接文档」等意图，或显式输入 `/session-handoff [update|rewrite] {用户指令}`。
- **禁止自动触发**：不得在任务完成、会话收尾时主动询问"是否保存进度"，不得在用户未明确要求时生成任何文档。
- **触发后先加载再执行**：读完本 SKILL.md 与 `references/handoff-template.md`，严格按本技能流程执行，禁止跳过技能内容、凭对话印象直接写文档。

## 二、子命令路由

调用格式 `/session-handoff [子命令] {用户指令}`：

| 调用方式 | 行为 |
| --- | --- |
| 无子命令 / `rewrite`（默认） | **新建**一篇交接文档 |
| `update` | **原地更新**本会话内引入的那篇进度文档 |

- **rewrite**：每次新建，禁止覆盖既有文档（当天同名追加 `-2`、`-3` 后缀）；用于本会话首次交接，或用户明确要求重新生成一份。
- **update**：更新对象**仅限当前会话内引入的进度文件**——本会话通过本技能生成的交接文档，或本会话续接时读取的那篇符合 `docs/progress/` 目录规范的文档；**绝不从历史记忆、历史会话中检索旧文档**。项目内不存在这样的文件时，退化为 rewrite 新建一篇并向用户说明。

## 三、执行红线（rewrite 与 update 全程遵守）

1. **只写文档，不做实现**：触发后唯一动作是生成或更新交接文档。用户指令夹带的实现诉求（如「保存进度，顺便把 X 修了」）一律拒绝执行，该诉求作为未完成事项如实写入文档；过程中发现的问题（代码缺陷、测试失败、遗漏步骤）只记录不修复，也不得为写文档继续展开调研或验证。
2. **内容只来自当前会话，且自包含**：每一条内容的唯一合法来源是本会话发生的设计、实现与产物事实。只记录本会话涉及的决策、实现、验证与产物状态；禁止「承接 / 参见上一份交接文档」式跨文档引用，禁止检索记忆系统或历史会话搬运内容，必要背景直接写明。做到**精确**（路径、命令、结论须查证自本会话真实操作，查证不到不写）、**完整**（新会话仅凭本文档即可续接，不留信息缺口）、**不冗余**（不堆砌与续接无关的细节，已完成部分只留一句话结论）。
3. **回报即封存**：文档生成或更新完毕并回报用户后，当前会话对该任务封存——停止一切任务实现：不写代码、不推进待办、不顺手修复记录在案的问题（update 只允许修改交接文档本身）。用户再要求续做已交接任务时，回答：「该任务已交接至新会话，请开启新会话并读取 `<交接文档绝对路径>` 后继续，本会话不再执行。」交接后的全新实现任务默认引导开新会话执行；仅纯信息查询（解释文档内容、确认路径等，不涉及任务实现）可当场回答。

## 四、rewrite 流程（默认，新建）

1. **定目录**：放在任务所属项目**真实根目录**的 `docs/progress/` 下，不要放在对话工具的临时会话目录（通常以时间戳自动生成），否则下次续接时找不到；目录不存在先创建。当前工作目录就是项目目录可直接用；无法确定时向用户确认项目绝对路径。
2. **定文件名**：`{yyyy-mm-dd}-{精简标题}.md`。日期为保存当天；标题不超过 15 个汉字、概括本次任务（如"待办工具cli实现"），任务描述模糊时先与用户确认再写入。
3. **读模板**：按 `references/handoff-template.md` 结构填写，模板顶部「交接声明」原样保留。
4. **填写要点**：已完成项每条一句话结论，让新会话知道哪些不用再做；未完成任务按模板子结构逐项填全——这是续接成败的关键，宁可写细不要省略，「下一步具体动作」必须写到可立即执行的命令/位置级别，禁止"继续做"式空话；环境依赖与全局约定按模板提示如实填写。
5. **填元信息**：`workspace_dir`（项目绝对路径）、`saved_at`（ISO8601 当前时间）、`生成方式: rewrite`、版本控制提交号（如 git commit hash，便于新会话检测环境漂移；无版本控制填 N/A）、任务一句话描述。
6. **回报交接宣言**：告知文档绝对路径与一句话总结（已完成几项 / 待续几项 / 从哪一步开始），并宣布：「本会话的任务已交接封存。请在【新会话】中打开 `<项目根>`，读取 `docs/progress/` 下最新的交接文档继续执行。」宣布完成后，按第三节红线 3 封存本会话。

## 五、update 流程（原地更新）

1. **定位更新对象**：按第二节定义定位本会话内引入的进度文件。
2. **只合并本会话新事实**：把用户指令中的新进展、修正、补充决策并入对应章节，同样受第三节红线约束。
3. **原地改写受影响章节**：已完成事项移入第 1 节、矛盾状态以最新为准、删除过时条目，保持文档自包含、无冗余、结构与模板一致。
4. **刷新元信息**：更新 `saved_at` 与版本控制提交号，`生成方式: update`；文件名与路径不变，不新建文件。
5. **回报用户**：告知更新了哪些章节，并重申封存状态（update 只维护文档，不解除封存）。

## 六、资源

- `references/handoff-template.md` — 交接文档模板，生成时必须严格遵循，顶部「交接声明」不可省略。
