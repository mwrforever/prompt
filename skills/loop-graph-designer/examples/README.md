# example 子命令 · 场景索引与使用规则

> 本目录独立维护 `/loop-graph-designer example {场景} {用户指令}` 的全部场景专项示例：每个场景一个独立文件（`examples/{场景}.md`），为真实历史任务的完整产出。SKILL.md 只保留本子命令的索引入口，使用规则以本文件为准；触发 example 模式后必须先读本文件。

## 场景索引

| 场景 | 示例文件 | 精简说明 |
| --- | --- | --- |
| `risk` | [risk.md](risk.md) | 项目风险扫描：全仓三路专项扫描（A 类高置信风险 / B 类 IO·DB 性能 / Q 类代码质量）→ 核证打分 → 逐项修复 → e2e 验收 → 门禁 PR 与审核合入的 graph 形态执行文档 |

## 使用流程

1. **场景校验**：按索引核对 `{场景}`；不在索引内（含场景名缺省）→ 立即按「场景未收录处理」结束，禁止凭空设计场景、禁止套用相近场景。
2. **澄清差异点**：按 SKILL 阶段 A 共用输入项一次问齐本次任务与场景示例的差异——目标项目根、执行范围与基线、产物路径约定、用户特别要求；指令已写明的不重复问。
3. **以场景示例为基架设计**：章节结构、节点划分、门禁与红线沿用示例做法；示例中的项目特定事实（路径、端口、命令、宪法文件、产物与分支约定等）**只借结构与做法，禁止照搬**，逐项替换为目标项目实际探查结果（只读探查），替换不到的转 `{待调研项}` 占位并设回填门禁；用户指令与示例基架冲突时以用户指令为准。
4. **收口**：任务与派遣遵守 SKILL 阶段 A 目标明确约束；文档设计进入 SKILL 阶段 B，交付前必经第五节审核优化循环。

## 场景未收录处理

用户请求的场景不在索引内时，**直接结束本次生成**（不产出任何文档、不套用相近场景），礼貌告知「{场景} 暂未收录」，并按列表展示可退化去向，等用户明确选择后再按对应模式重新开始；未选择前不产出任何文档：

| 可选去向 | 精简说明 |
| --- | --- |
| `example risk` | 场景化专项：按项目风险扫描示例生成全仓扫描 → 核证 → 修复 → 验收 → PR 合入的执行文档 |
| `spec {功能文档列表} {附加指令}` | 已有功能文档：确认实际内容后按「一份 spec = 一个任务」排期出文档，不探索实现方案 |
| `input {用户需求}` | 无功能文档：澄清需求并提出 2-3 种方案，用户确认后按模块拆分排期出文档 |
| `skill {技能列表} {附加指令}` | 协同其它技能：核实技能实际能力后编排进执行文档对应阶段 |

※ 场景收录扩充后，「example」行按上方场景索引逐条展开；新增场景 = 在本目录新增独立示例文件并在索引表登记一行。
