# 项目宪法 AGENTS.md 模板（章节骨架）

> 本文件定义 `constitution-generator` 生成 AGENTS.md 的**必含章节骨架与逐章填写规则**。生成时逐章套用，禁止缺章、禁止改变章节编号结构。Part B（架构层）/ Part C（前端）按项目技术栈实际**整体省略或保留**，Part D（项目实际）必有。方括号 `[...]` 为占位说明，生成时必须替换；**信息不可得时允许 `{待调研项}` 占位（禁止编造），须在附录集中登记**；`※` 标注为规则性说明，不写入最终文档。

## 文档头（生成文档最顶部）

```markdown
# {项目名} 项目宪法

> 项目最高规范：**只存原则、约束与数据契约**。功能实现细节见代码与 `{任务索引文件，如 TASK.md}`，本文档不重复。
> 任何与本文档冲突的代码或设计不得合入主分支。
> {若引用全局约束文件} 注释 / 日志 / 测试覆盖规范见全局 `{全局约束文件路径}`（§一/§二/§六），本项目不重复正文，强制生效。

**{N} 段结构**：Part A {语言/后端框架} 通用 / {Part B {架构层描述} / Part C 前端 /} Part D {项目名} 实际。
```

※ 头注三要素：只存原则约束的定位声明、违者不合入主分支、引用全局规范（存在才写）。Part 编号固定（A 通用 / B 架构层 / C 前端 / D 项目实际）；省略段时编号不重排。

## Part A — {语言}+{后端框架} 通用规范

### A.1 编码约束（调研主题：语言 + Web 框架）

1. 编码/行尾/版本约束（如 UTF-8、LF、语言版本下限）
2. 类型要求（type hint / 严格类型模式，按调研结果）
3. 异步/并发界限（async 约束、禁止异步上下文内同步阻塞等）
4. 输出约束（日志 vs print、禁止裸输出）

### A.2 配置管理（调研主题：语言 + Web 框架 / 部署）

1. 配置分层（非敏感配置文件 + 敏感 env 分离）
2. 敏感值占位与注入方式
3. 模板文件要求（如 `.env.example` / `config.example.yaml`）

### A.3 API 设计（调研主题：语言 + Web 框架）

1. 版本化前缀
2. 请求/响应契约（框架的契约模型，禁止裸 dict 等）
3. 统一错误响应格式与 HTTP 状态码语义

### A.4 数据库操作（调研主题：ORM + 迁移 + 数据库；无 DB 则整节省略）

1. 表结构变更强制迁移（含 upgrade/downgrade 或等价机制）
2. 会话/连接生命周期约定（异步 session、禁止请求内同步等）
3. 查询与索引约束（禁止全表扫描等）

### A.5 基础设施生命周期（调研主题：缓存 + 消息队列 / 部署；无则省略）

1. 进程级单例 / 显式生命周期（fail-fast）
2. 依赖获取方式（工厂式 DI，禁止直接 import 单例）
3. 线程池 / 异步调度约束
4. 后台任务强引用 / 生命周期管理
5. 消息流模式（消费组、重试、幂等、取消——按调研结果）

### A.6 注释 / 日志 / 测试（引用全局，不重复）

```markdown
见 `{全局约束文件路径}` §…。本项目强制生效。
```

※ 无全局约束文件可引用时，本段按调研主题「构建 + 测试 + CI 门禁」产出条目直接写入宪法。

## 填写规则（生成自查清单）

1. 只写**原则、约束与数据契约**三类内容；"怎么实现"不留，留给代码与任务索引文件
2. 每条条款有调研来源支撑（来源记在调研报告，宪法正文不逐条标注）
3. 版本必须来自用户提供或勘察证据，禁止编造
4. 跨主题冲突裁决：官方文档 > 厂商实践 > 社区实践
5. 引用全局约束文件时章节号以实际文件为准（先读后写）
6. 生成前核查：结构完整、无编造、无实现细节、无重复全局规范正文、全部 `{待调研项}` 已登记
