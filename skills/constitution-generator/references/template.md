# AGENTS.md 分层文档体系模板（章节骨架）

> 本文件定义 `constitution-generator` 生成**分层宪法文档体系**的必含章节骨架与逐章填写规则：
> - 根 `<根>/AGENTS.md` 为**定位层**（模板一）——只做项目定位、一层目录地图、子项目宪法索引与跨切总则；
> - 每个技术子项目 `<子项目>/AGENTS.md` 为**子宪法**（模板二）——承载该子项目的全部宪法深度；
> - `<根>/CLAUDE.md` 为**唯一根索引**（模板三）——全项目仅一份索引文件，md 链接列全定位层与全部子宪法；
> - **整仓单应用**（依赖清单位于仓库根、无并列技术子目录）时只产出一份子宪法，落 `<根>/AGENTS.md`，省略模板一，根索引照常生成。
>
> **模式命名映射**：本模板以 agent 模式（AGENTS.md 宪法体系 + CLAUDE.md 根索引）表述；claude 模式（`/constitution-generator claude`）执行时做全局命名对调——宪法体系文件 `AGENTS.md` → `CLAUDE.md`、根索引 `CLAUDE.md` → `AGENTS.md`，章节结构与填写规则不变。全项目仅根目录一份索引文件，**禁止在各子项目目录生成索引文件**（SKILL.md §二）。
>
> 生成时逐章套用，禁止缺章、禁止改变章节编号结构。方括号 `[...]` 为占位说明，生成时必须替换；**信息不可得时允许 `{待调研项}` 占位（禁止编造），须在 TASK.md 登记表（无 TASK.md 时子宪法附录）集中登记**；`※` 标注为规则性说明，不写入最终文档。

# 模板一 · 根 AGENTS.md（定位层）

> 角色定位：**仓库导览层**——只做整个仓库的地图与索引，深度一律指向子宪法；在子项目内部工作时读该子项目的 AGENTS.md 而非本文档。正文 ≤ 200 行（默认，见 SKILL.md §三「行数与去重要求」）。

## 文档头（生成文档最顶部）

```markdown
# AGENTS.md

> 本文件为 AI 编码代理提供仓库级指引，是**定位层**：只描述项目定位、**根目录一层**结构与子项目宪法索引，不承载任何子项目内部的深度约束。
> **强制阅读路由**：写任一子项目代码前必读其宪法（逐子项目路径与深度范围见下文「子项目宪法索引」，此处不复述）；本文档只是地图与索引，子项目内的任何深度约束以子宪法为准。
> {若引用全局约束文件} 注释 / 日志 / 测试规范见全局 `{全局约束文件路径}`（§…），本项目不重复正文，强制生效。
```

※ 全局约束文件引用与各子宪法保持同源同章节号（多处引用属「索引」，不属「重复正文」）。
※ **强制阅读路由为必含项**：文档头保留规则句「写任一子项目代码前必读其宪法」并指向第 5 章；**子项目宪法索引全文只在第 5 章描述一次**（路径 + 深度范围），文档头不得复述链接与深度范围，其余章节只留指针。

### 1. 项目定位

2–4 句：一句话业务定位 + 各子项目角色概述（后端做什么、前端做什么、外部接入等）。只写"是什么"，不写技术细节（技术细节归子宪法）。

### 2. 运行形态（可选：多服务协作时）

表：服务 | 端口/入口 | 职责。原则级描述协作关系（谁代理谁、单一公网入口、内部端口不外暴等），运行与路由细节归对应子宪法。

### 3. 仓库地图（**仅一层**）

```markdown
{项目名}/
├── Makefile                    # 根编排命令（见下「命令总览」）
├── config.example.yaml         # 模板 → 复制为 config.yaml（根运行时配置，实文件 gitignore）
├── AGENTS.md / CLAUDE.md       # 定位层 / 唯一根索引（全项目仅此一份索引文件）
├── TASK.md                     # 待办与登记台（{待调研项} / 待决策 / TODO 工单）
├── CHANGELOG.md                # 工程变更记录（宪法修订先记此处再改正文）
├── backend/                    # Python 后端 —— 规范见 backend/AGENTS.md
├── frontend/                   # Next.js 前端 —— 规范见 frontend/AGENTS.md
├── docker/                     # 容器编排与反向代理配置
├── scripts/                    # 根编排脚本
├── docs/                       # 跨切文档
│   ├── specs/                  # 功能设计与业务数据契约（子宪法只引用不重复）
│   └── agmds-research/         # 宪法调研报告
└── tests/                      # 根级测试
```

※ **只画一层**：每个子目录一行职责注释；技术子项目行尾必标「规范见 <子项目>/AGENTS.md」；**禁止展开子项目内部目录**（子项目内部 tree 归其子宪法 C.3 目录结构）。
※ **宪法关联目录职责必写**：宪法体系引用的根级目录（`docs/specs/` 功能设计与数据契约、调研报告目录、TASK.md / CHANGELOG.md 等）必须在地图中写明职责，允许对这类**非技术目录**下钻一层标注；技术子项目内部仍一个字不展开。
※ 运行时配置的跨切说明（配置放哪、模板复制关系、经谁编辑）可在此补 2–3 句，配置结构细节归对应子宪法。

### 4. 命令总览（根 vs 子项目）

根编排命令代码块（全栈起停 / 安装 / 检查 / 部署，含一句注释）+ 一句口诀：**根命令 = 整个应用；子项目内命令 = 单模块工作**。子项目内命令各举 1–2 例并指向子宪法，禁止展开子项目全量命令清单。

### 5. 子项目宪法索引（必含）

| 子项目 | 宪法 | 深度范围（一句话） |
|---|---|---|
| backend/ | [backend/AGENTS.md](backend/AGENTS.md) | {如：运行时与路由、架构分层、持久化与迁移、配置系统、测试布局} |
| frontend/ | [frontend/AGENTS.md](frontend/AGENTS.md) | {如：页面结构、状态与数据流、视觉令牌、代码风格与命令} |

※ 路径与深度范围描述必须与实际落盘的子宪法一一对应（SKILL.md §五.5 审核专项）；非技术目录（docs/、docker/、scripts/）不入本索引。
※ 本索引是**全文唯一**的子项目宪法描述落点：文档头只保留路由规则句并指向本节，其余章节（仓库地图、去哪里深入）只留指针、不复述深度范围；在该子项目内写代码前**必读**其宪法。

### 6. 跨切约定

repo 级原则条目，每条 1–3 行，**只写总则**，细节归对应子宪法：
- **配套文件职责** —— `TASK.md` 待办与登记台（{待调研项} / 待决策 / TODO 工单，回填后删除对应行）；`CHANGELOG.md` 工程变更记录（宪法修订与重大变更，**先记变更再改正文**）；`docs/` 过程文档（含 agmds-research 调研报告）
- 文档同步策略（用户可见变更更 README，架构/开发规范变更更对应 AGENTS.md，同一变更集内完成）
- 全栈门禁总则（合入主干前各子项目 lint + format + 测试全过；各语言工具链与命令归子宪法）
- 跨子项目协作契约（如统一 API 前缀、contracts/ 目录、共享数据契约）——细节在哪个子项目就指向哪个子宪法

### 7. 去哪里深入

列表：各子项目开发 → 见「子项目宪法索引」（写代码前必读其宪法，此处不复述索引）；功能设计与数据契约 → `docs/specs/`；待办登记 → TASK.md；变更记录 → CHANGELOG.md；安装 / 贡献 / 安全策略 / 发布 → 对应根级文档（README.md、CONTRIBUTING.md、SECURITY.md 等，按项目实存列）。

## 填写规则（生成自查清单）

1. 子宪法只写**工程原则与约束**两类内容（定位层另含索引/地图/总则）；"怎么实现"与业务数据契约不留——归代码与 `specs/`
2. 每条条款有调研来源支撑（来源记在调研报告，宪法正文不逐条标注）
3. 版本必须来自用户提供或勘察证据，禁止编造
4. 跨主题冲突裁决：官方文档 > 厂商实践 > 社区实践
5. 引用全局约束文件时章节号以实际文件为准（先读后写）；定位层与各子宪法引用同源同章节号
6. 生成前核查：结构完整、无编造、无实现细节、无重复全局规范正文、全部 `{待调研项}` 已登记
7. **行数上限**：各文档正文 ≤ 对应上限（定位层默认 200 行 / 子宪法默认 500 行），超限必须砍重复/实现细节/功能设计
8. **归属与去重**：全局硬约束 = **所有**子项目共有的约束，才可上收定位层且只写总则；子项目约束（含兄弟子项目间相同的栈 / 门禁细则）全文写入各自子宪法，禁止互引共享、宁可重复；说明性内容（定位、目录地图、目录结构）各归其位只出现一次，子宪法不复制根地图或兄弟子宪法的说明；定位层的子项目宪法索引全文只落「子项目宪法索引」一处
9. **功能设计边界**：业务数据模型、图模型节点/关系清单、状态机事件、业务计算规则等一律不写入宪法，只留指向 `specs/` 的职责行
10. **变更记录外置**：宪法正文不设变更控制/变更记录章节；修订流程 = 先记 `CHANGELOG.md` 再改正文，语义由头注「配套文件职责」承载
11. **归属规则**：约束归属其子项目宪法——前端约束不写进后端子宪法，子项目深度约束不写进定位层；多子项目共有的子项目约束各自完整写一份（宁可重复），禁止引用兄弟子宪法；跨切约定只收**所有**子项目共有的总则，细节归对应子宪法
12. **一层目录规则**：定位层仓库地图以根目录一层为准，宪法关联的根级目录职责必写（`docs/specs/`、调研报告目录等，允许下钻一层标注）；技术子项目内部结构禁止展开，归该子宪法 C.3 目录结构
13. **引用链一致性**：定位层索引中的路径与深度范围描述必须与实际落盘的子宪法一一对应；子宪法头注反指定位层；引用（含章节号与路径）不算重复正文，复制正文才算
14. **强制路由规则**：定位层必含强制阅读路由——文档头保留规则句「写任一子项目代码前必读其宪法」并指向索引章节；逐子项目路径与深度范围只在「子项目宪法索引」章节描述一次，头与索引不得两处复述
15. **唯一根索引规则**：全项目仅一份索引文件，落项目根、命名与宪法体系相反（agent 模式 = `CLAUDE.md`，claude 模式 = `AGENTS.md`）；全部用 md 链接语法列全根定位层、全部子宪法与配套文件；纯索引不写规范正文；链接路径与实际文件一一对应，宪法文件路径调整时同步更新；**禁止在各子项目目录生成索引文件**
16. **常用命令规则**：每份子宪法 Part C 必含 C.4 常用命令节——打包 / 构建、测试、格式化、修复（lint --fix）、启动等按实际工具链列全；根定位层「命令总览」只举 1–2 例并指向各子宪法 C.4，不展开子项目全量命令
17. **引用实存规则**：宪法引用的设计文档（`specs/` 等）与项目材料必须来自用户本次输入或当前工作区实存探查（先确认路径存在再写入）；禁止基于项目历史记忆、全局记忆或历史会话关联旧 / 临时设计文档——实存缺失就不引用，登记 `{待调研项}`
