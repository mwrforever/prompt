# 分层宪法模板（章节骨架）

> 本文件是产出物**结构与约束方向的唯一权威**：模板一 = 根定位层，模板二 = 子项目宪法，模板三 = 根索引。
> **命名映射**：以 agent 模式表述（AGENTS.md 宪法实体 + CLAUDE.md 根索引）；claude 模式全局对调命名，结构与规则不变。两种宪法**必然同时生成**——一方承载实体、一方做索引；索引只落根目录一份，**禁止在子项目目录生成索引文件**（SKILL.md §一）。
> `[...]` 为占位说明，生成时替换；信息不可得写 `{待调研项}`（禁止编造，登记 TASK.md）；`※` 为填写规则，不写入最终文档。

# 〇、宪法基础框架（调研与合成的统一目标）

## 层级依赖

```text
根索引（<根>/CLAUDE.md，纯 md 链接，根目录仅此一份）
    └─链接可达─▶ 根定位层（<根>/AGENTS.md：定位 / 地图 / 路由 / 索引 / 效力总则 / 跨切总则）
                     └─强制阅读路由─▶ 子宪法 ×N（<子项目>/AGENTS.md：深度唯一承载）
                                          └─职责引用─▶ specs/（业务设计）· TASK.md（登记）· CHANGELOG.md（变更）
```

**权威顺序**（写入定位层 §6）：单子项目事项以其子宪法为准；跨子项目事项以定位层为准；两者均未规定者按通用工程惯例处理，并在 `TASK.md` 登记待决策。

## 必含章节与约束方向

| 文档 | 必含章节 | 约束方向 |
|---|---|---|
| 根定位层 | 文档头；1 项目定位；2 运行形态（多服务时）；3 仓库地图（仅一层）；4 命令总览；5 子项目宪法索引；6 约束效力与遵从总则；7 跨切约定；8 去哪里深入 | 地图只画一层，宪法关联目录职责必写；§6 声明定位层 + 全部子宪法强制生效、冲突不合入、裁决顺序；跨切只收所有子项目共有总则（含 CI 链总则）；「配套文件职责」声明唯一落点 |

| 根索引 | 纯 md 链接清单 + 强制阅读路由复现 | 不写规范正文，链接与实存一一对应 |

**用户钉版条款**：生成或修订中用户明确钉定的约束，行尾标注「{yyyy-MM-dd} 用户钉版」；钉版条款的修订必须先经用户确认，禁静默改写（适用于定位层与全部子宪法）。

## 调研槽位映射

- **本地宪法库优先**：派遣前逐主题查技能包本地宪法库——栈宪法查 `data/stack/{技术栈}.md`、CI 段查 `data/ci/{语言}.md`（命中判定与回写规范见 SKILL.md §四/§五）：全命中直接复用、部分命中仅缺失槽位派遣；命中条目按槽位进入合成，效力等同调研报告。
- 派遣必标注：归属文档 + 目标槽位（章节号）+ 必备约束方向；报告按槽位分节，评审按槽位核对（SKILL.md §四/§七）。
- **内置条款不依赖调研**：约束效力总则、A.7 三原则与例外边界、C.4 / C.5 骨架按模板直写；调研只补本栈习语与流水线细则。
- **CI 先行**：CI 链方案先经用户确认（SKILL.md §三/§六.1；技术栈已定且 `data/ci/{语言}.md` 命中时优先由库内 CI 段组装方案），确认前不得调研、定稿其它槽位。
- 可省略槽位（A.3 / A.4 / A.5 / Part B、定位层「运行形态」）省略时编号不重排；必含槽位禁止缺章。

# 模板一 · 根 AGENTS.md（定位层，≤ 200 行）

> 仓库导览层：只做地图与索引，深度一律指向子宪法。

## 文档头

```markdown
# AGENTS.md

> 本文件为 AI 编码代理提供仓库级指引，是**定位层**：只描述项目定位、**根目录一层**结构与子项目宪法索引，不承载子项目内部深度约束。
> **强制阅读路由**：写任一子项目代码前必读其宪法（见「子项目宪法索引」）；主控触碰子项目内容或派遣 subagent 均须先加载对应子宪法（见 §6）；子项目内的深度约束以子宪法为准。
> **约束效力**：本定位层（含跨切总则）与全部子项目宪法对所有开发行为强制生效，冲突代码 / 设计不得合入主分支（总则见 §6）。
```

※ 路由规则句只在文档头出现一次；逐子项目路径与深度范围只在 §5 描述一次，两处不得复述。

### 1. 项目定位
2–4 句：业务定位 + 各子项目角色，不写技术细节。

### 2. 运行形态（多服务协作时）
表：服务 | 端口/入口 | 职责；原则级协作关系（如单一公网入口、内部端口不外暴），细节归子宪法。

### 3. 仓库地图（仅一层）

```markdown
{项目名}/
├── Makefile                    # 根编排命令（见「命令总览」）
├── AGENTS.md / CLAUDE.md       # 定位层 / 根索引（全项目仅此一份索引）
├── TASK.md                     # 待办与登记台（{待调研项} / 待决策 / TODO）
├── CHANGELOG.md                # 工程变更记录（先记再改正文）
├── backend/                    # Python 后端 —— 规范见 backend/AGENTS.md
├── frontend/                   # Next.js 前端 —— 规范见 frontend/AGENTS.md
├── docker/                     # 容器编排与反向代理
├── docs/
│   ├── specs/                  # 功能设计与业务数据契约（宪法只引用）
│   └── agmds-research/         # 宪法调研报告
└── scripts/                    # 根编排脚本
```

※ 每目录一行职责；技术子项目行尾必标「规范见 <子项目>/AGENTS.md」，内部结构禁止展开（归其子宪法 C.3）；宪法引用的根级目录（docs/specs/ 等）职责必写，非技术目录可下钻一层。

### 4. 命令总览（根 vs 子项目）
根命令代码块（全栈起停 / 安装 / 检查 / 部署，各带一句注释）+ 口诀：**根命令 = 整个应用；子项目内命令 = 单模块工作**。子项目命令各举 1–2 例，全量清单指向其子宪法 C.4。

### 5. 子项目宪法索引（必含）

| 子项目 | 宪法 | 深度范围（一句话） |

※ 路径与深度范围与实际落盘的子宪法一一对应（审核专项）；非技术目录不入索引。

### 6. 约束效力与遵从总则（必含，条目不随技术栈变化）

1. **强制生效**：本定位层（含跨切总则）与全部子项目宪法对一切开发行为（编码 / 设计 / 脚本 / CI / 文档）强制生效。
2. **不得违背**：冲突以宪法为准，冲突产物不得合入主分支；禁止「临时 / 紧急」绕过——修宪先记 `CHANGELOG.md` 再改正文，一次性事项登记 `TASK.md` 待决策并限定范围。
3. **遵从路径**：开发任一子项目前必读其宪法；跨子项目行为同时遵守跨切总则。主控 agent 自行触碰或加载某子项目内容前，必须先加载该子项目宪法；派遣 subagent 执行涉及某子项目的工作时，派遣任务内容中必须显式标注「先实际加载该子项目宪法（路径）并严格遵守其全部约定」——subagent 上下文独立、不继承主控已加载内容，未加载对应子宪法不得开工。
4. **裁决顺序**：单子项目事项以其子宪法为准；跨子项目事项以本文档为准；两者均未规定者按通用工程惯例处理并在 `TASK.md` 登记待决策。
5. **插件技能加载纪律（技能先行）**：凡任务命中已装配的插件技能（skill）——先实际加载技能正文再实现，不能猜；仅当该技能 ≥90% 可能适用于当前场景时才加载；只在对应任务开工前加载，禁止为后续任务预测性预载。技能正文常分层组织：SKILL.md 仅为索引入口，必须按需跟进加载其以相对路径链接的子文档（相对技能根目录解析），只读 SKILL.md 不视为完成加载。派遣 subagent 时，派遣指令须载明所需技能与上述分层加载要求（subagent 上下文独立、不继承主控加载状态）。
6. **跨端分治派遣**（多子项目任务场景）：分治在任务诞生时即完成——任务列表 / 执行文档必须按子项目原生拆分，每个任务的修改范围禁跨越子项目边界；凡需求涉及 ≥2 个子项目（任意前后端 / 双前端 / 双后端组合），必须拆为每端独立任务并各派遣独立 subagent，禁止一个 subagent 一次或连续承担多端改动（多套子宪法约束同上下文混载必然导致约束偏离）；主控只承担编排：任务拆解、下发跨切公共事实（接口契约 / ID / 鉴权约定等）、集成与验收；例外：只读勘察 / 调研类工作不受此限。

### 7. 跨切约定
repo 级总则，每条 1–3 行，细节归对应子宪法：
- **配套文件职责**（全体系唯一声明落点）—— `TASK.md` 登记台；`CHANGELOG.md` 变更记录（先记再改）；`docs/` 过程文档
- 文档同步策略；全栈门禁总则
- **CI 链总则** —— 全项目 CI 工具与统一门禁原则（按选定方案）；各子项目流水线细则归其子宪法 C.5
- 跨子项目协作契约（统一 API 前缀、契约目录等）

### 8. 去哪里深入
各子项目开发 → §5 索引（写代码前必读其宪法）；设计与契约 → `docs/specs/`；登记 → `TASK.md`；变更 → `CHANGELOG.md`；安装 / 贡献 / 安全 → 根级实存文档（README.md、CONTRIBUTING.md 等）。

## Part A — {技术栈} 通用规范

> Part A 可按栈需要增设 A.9+ 槽位（编号顺延，如「A.9 响应式与图标纪律」）；新增槽位须在文档内一句话声明职责，禁挤占既有槽位编号。

### A.1 编码约束（调研：语言 + 框架）
编码 / 行尾 / 版本下限；类型要求；异步界限（禁异步上下文同步阻塞）；输出约束（禁裸输出）。

### A.2 配置管理
配置分层（非敏感文件 + 敏感 env）；敏感值占位注入；模板文件（`.env.example` 等）。

### A.3 API 设计（无对外 API 整节省略）
版本化前缀；请求 / 响应契约模型（禁裸 dict）；统一错误格式与状态码语义。

### A.4 数据库操作（无 DB 省略）
表结构变更强制迁移（upgrade / downgrade）；会话 / 连接生命周期；查询与索引约束。

※ 内容量大时可分为 A.4.1 迁移与 Schema / A.4.2 连接、事务与数据规范 / A.4.3 {ORM} 使用规范 三小节（省略槽位编号不重排规则同样适用）。

### A.5 基础设施生命周期（无则省略）
进程级单例 + 显式生命周期（fail-fast）；依赖工厂注入；后台任务强引用；消息流（消费组、幂等、有界重试）。**只收原则级条款**——机制细节（消息语义、断线续传、并发校验、供应商接入清单等）归定稿 / `specs/`，正文留指针条款（「机制设计见 X，不写入宪法」）。前端子宪法本槽为渲染性能：动效性能铁律**属性级**成文——逐帧仅 transform / opacity 合成属性（与动效工具无关），布局类动效为唯一例外通道（经 FLIP 机制承载），工具分工条款归 A.1、两者禁冲突。

### A.6 注释 / 日志 / 测试（无本项目额外约束则整节省略）
注释 / 日志 / 测试的通用纪律随编码工具自动加载，宪法不重复抄录、不声明引用。本槽只写**本项目在通用纪律之外的额外约束**（如测试分层方式、覆盖率门槛、日志字段要求），无额外约束即整节省略（编号不重排）。

### A.7 跨层数据对象与传参约束（必含·体系内置）
前后端通用三原则 + 例外边界，**必须按本栈习语翻译后成文**（后端 = 参数对象 / 请求 / 响应模型等；前端 = interface / type / props 等），禁照抄抽象表述：

1. **参数对象化**：公开方法形参 > 3 必须参数对象整体传参，禁逐参罗列；仅业务确需灵活传参可例外。
2. **返回业务对象**：业务返回必须业务对象（禁裸 dict / Map 等无结构载体）；请求与响应分别建模，禁同一对象双向复用（A.3 省略时本条承载请求 / 响应建模）。
3. **职责隔离**：不同业务职责对象禁复用——字段全同也按职责各自建类（查询参数 ≠ 响应对象 ≠ 存储模型）；禁万能对象承载多职责、禁跨层直传。
4. **例外边界**：仅业务功能确需动态 / 灵活结构可偏离，且须能陈述业务理由；无理由的违反视为缺陷，不得合入。

## Part B — 架构分层（无分层架构整段省略）

> 目录职责统一由 C.3 目录结构承载（目录 + 行尾职责与边界一体化），Part B 不另设目录职责清单。

### B.1 层级依赖（强制）
依赖方向图（text）；禁跨层调用、反向依赖、循环 import；事务边界归属；跨子项目 / 跨域能力分工按业务功能域级声明（禁按具体表或对象钉死）。

### B.2 运行时原则
核心运行循环（并发 / 取消 / 重试 / 清理）——以调研为准，不臆造。

### B.3 {外部能力}网关（无则省略）
能力注册表、路由规则、凭证约束、请求记录要求。

### B.4 横切关注点
安全 / 审计 / 限流 / HITL 等，每条一行原则，不写实现。

## Part C — {子项目名} 实际

### C.1 子项目定位
一句话角色定位；禁功能清单与流程展开（细节归 `specs/` / README）。

### C.2 技术栈选型
