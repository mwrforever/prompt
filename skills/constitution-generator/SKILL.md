# 项目宪法生成器（AGENTS.md / CLAUDE.md 双入口）

> 职责：基于项目的技术栈，派发 subagent 调研各技术栈的官方文档与厂商最佳实践，把调研结果提炼为「只存工程原则与约束」的**分层宪法文档体系**：
> - **宪法体系**（文件命名随子命令，见 §二）：`agent` 模式（默认）整个体系命名为 AGENTS.md，`claude` 模式整体命名为 CLAUDE.md。体系 = **根定位层**（`<根>/AGENTS.md`：项目定位、**根目录一层**目录地图、命令总览、**强制阅读路由**（写某子项目代码必读其宪法）、子项目宪法**索引**与跨切约定总则，不承载任何子项目内部的深度约束）+ **子项目宪法** ×N（每个技术子项目目录各一份，承载该子项目的全部宪法深度；业务功能设计与数据契约不写入，只留指向 `specs/` 的职责行）；
> - **唯一根索引**：整个体系只配**一份**根级索引文件（`<根>/CLAUDE.md` 或 `<根>/AGENTS.md`，命名与宪法体系相反），纯 md 链接列全根定位层与全部子宪法，不写任何规范正文——索引文件被工具加载后经链接**间接可达**全部宪法，**禁止再在各子项目目录生成索引文件**。
>
> 定位层与子宪法的书面风格见 `references/example.md`。调研一律派遣 subagent 执行，主控代理只做编排（输入锁定、子项目判定、派遣协调、报告评审、章节合成、审核派遣、落盘）。两模式除文件命名外流程完全一致，下文统一以 agent 模式（AGENTS.md）表述，claude 模式按 §二 命名映射替换。

## 一、何时使用

- 用户要"根据技术栈生成项目宪法 / AGENTS.md / 项目规范文件"
- 用户要求"派发 subagent 调研各大厂商对该技术栈的最佳实践后产出一份规范"
- 用户贴出示例（根一层目录地图 + 子项目宪法索引的分层规范）要求"生成类似的宪法"
- 用户要求"前后端约束分开 / 根目录只做索引 / monorepo 各模块一份规范"
- 用户给出技术栈清单，要求"写成供编码代理执行的约束规范"

## 二、子命令路由

调用格式：`/constitution-generator [claude|agent] {用户指令}`，子命令决定**宪法体系的文件命名**与根索引文件名：

| 调用方式 | 模式 | 宪法体系命名 | 唯一根索引 |
| --- | --- | --- | --- |
| `/constitution-generator agent {用户指令}` 或无子命令 | **agent（默认）** | `<根>/AGENTS.md`（定位层）+ `<子项目>/AGENTS.md` ×N（子宪法） | `<根>/CLAUDE.md` |
| `/constitution-generator claude {用户指令}` | claude | `<根>/CLAUDE.md`（定位层）+ `<子项目>/CLAUDE.md` ×N（子宪法） | `<根>/AGENTS.md` |

- **默认 agent**：首个 token 不是 `claude` / `agent` 时按无子命令处理，整段输入视为用户指令，走 agent 模式。
- **两模式流程完全一致**（模板、调研、合成、审核、落盘全同），仅文件命名整体对调：本技能正文与模板以 agent 模式表述，claude 模式执行时做全局命名映射——宪法体系文件 `AGENTS.md` → `CLAUDE.md`、根索引 `CLAUDE.md` → `AGENTS.md`，章节结构与内容规则不变；**禁止体系内命名混用**（一半 AGENTS.md 一半 CLAUDE.md）。
- **索引只此一份**：无论何种模式，禁止在子项目目录再生成任何索引文件（`CLAUDE.md` / `AGENTS.md` 均不得）——根索引被工具加载后经 md 链接间接可达全部子宪法，逐目录重复索引属于冗余文件。
- **整仓单应用**：agent 模式 = `<根>/AGENTS.md`（宪法）+ `<根>/CLAUDE.md`（索引）；claude 模式 = `<根>/CLAUDE.md`（宪法）+ `<根>/AGENTS.md`（索引）。

## 三、输入收集（一次问齐，不反复打扰）

| 输入 | 说明 | 缺省 |
|---|---|---|
| 项目名与定位 | 一句话业务描述 | 当前工作区目录名 |
| 技术栈清单 | 按**子项目**分域给出：语言 / Web 框架 / ORM / 数据库 / 缓存 / 消息队列 / 图数据库 / agent 框架 / LLM 网关 / 前端 / 构建与 CI；可粘贴或指向配置文件（pyproject.toml、package.json 等）；未提供时派遣「项目勘察」subagent 扫描项目根推断 | 必填，缺失才问或勘察 |
| 子项目清单 | 根目录一层内带独立依赖清单（pyproject.toml / package.json / go.mod 等）的技术子项目目录与各自职责（如 backend=API 网关、frontend=Web UI）；非技术目录（docs/、scripts/、docker/）不入宪法体系，只在根目录地图标注。**整仓单应用**（依赖清单位于仓库根、无并列技术子目录）视作唯一子项目：只产出该子项目宪法（落仓库根，agent 模式 `<根>/AGENTS.md`、claude 模式 `<根>/CLAUDE.md`），不另生成定位层 | 勘察判定 |
| 全局约束文件 | 是否引用已有全局 AGENTS.md/CLAUDE.md（如 `~/.zcode/AGENTS.md`）——宪法只引用其注释/日志/测试规范段落，不重复正文；缺失时探测常见全局位置，找不到则不引用 | 探测常见全局位置，无则不引用 |
| 项目特有材料 | 既有架构/设计文档（`specs/` 等）路径——子宪法只引用其路径与职责，不复制内容；仅认用户本次给出或工作区探查实存的路径，禁止凭历史/全局记忆补全 | 无 |
| 行数与去重要求 | 定位层 ≤ 200 行（默认）、每份子宪法各 ≤ 500 行（默认）；超限必须精简：砍重复、实现细节、功能设计；重复边界见 §七「归属与去重」——定位层只写所有子项目共有的总则，子项目约束各自写全（宁可子宪法间重复），说明性内容不复制 | 200 / 500 |
| 登记/变更文件 | 待回填登记表落 `TASK.md`、变更记录落 `CHANGELOG.md`（项目已有则沿用，无则新建；**均为根级**，各子宪法共用）；定位层与子宪法头注以「配套文件职责」列明各文件边界；**宪法正文不设变更控制/变更记录章节** | 外置 TASK.md / CHANGELOG.md |
| 输出位置 | 由 §二 子命令决定：agent 模式（默认）= `<根>/AGENTS.md`（定位层）+ `<子项目>/AGENTS.md` ×N + 根索引 `<根>/CLAUDE.md`；claude 模式 = `<根>/CLAUDE.md` + `<子项目>/CLAUDE.md` ×N + 根索引 `<根>/AGENTS.md`；整仓单应用时仅根宪法 + 根索引两份 | 当前工作区 |
| 修订模式 | 目标已存在本模式将写入的任一文件（根定位层 / 子宪法 / 根索引）→ 默认另存 `*.draft`；或用户明确要求覆盖（覆盖前须先备份旧文件） | 另存 draft |

- 引用全局约束文件时，宪法头部引用的章节号必须与该文件实际章节一致（先读该文件核对再写入）；定位层与各子宪法的全局引用必须同源同章节号。
- 技术栈版本一律以用户提供或勘察到的 lockfile/配置文件实测为准，禁止编造。
- **引用来源红线**：宪法引用的一切项目材料（`specs/` 等设计文档、职责行指向的路径）一律以**当前目标项目工作区实存**为准——路径经探查确认存在后才可写入；禁止基于项目历史记忆、全局记忆或历史会话去关联旧设计文档 / 临时设计文档，记忆中的「曾有 specs/xxx」不作为引用依据；工作区实存缺失就不引用并登记 `{待调研项}`，凭记忆建链会污染宪法内容。

## 四、技术栈分域与调研主题划分（不过度拆分）

调研主题按技术栈组件族生成，**强耦合组件合并为一题**（语言+Web 框架、ORM+迁移+数据库、缓存+消息流各一题），避免拆到单个库：

| 典型主题 | 覆盖组件 | 子宪法段落落点 |
|---|---|---|
| 语言 + Web 框架 | 如 Python 3.12 + FastAPI | A.1 编码约束 / A.3 API 设计 |
| ORM + 迁移 + 数据库 | 如 SQLAlchemy 2.0 + Alembic + PostgreSQL | A.4 数据库操作 |
| 缓存 + 消息队列 | 如 Redis + Stream/消费组 | A.5 基础设施生命周期 |
| 图数据库 | 如 Neo4j（连接 / 查询 / 生命周期约束） | A.5 基础设施生命周期；业务图模型契约归 `specs/` 职责行 |
| 架构 / agent 框架 | 如 LangGraph（图 / checkpoint / HITL / 运行时） | Part B 全部 |
| LLM / 媒体网关 | 如 litellm + 厂商 SDK + 模型注册表 | B.4 网关 |
| 前端框架 + UI 栈 | 如 Next.js + TS + Tailwind + UI 组件库 | 前端子宪法 A.1 编码约束 / B 架构分层 |
| 构建 + 测试 + CI 门禁 | 如 uv / ruff / pytest / pre-commit / Actions | 各子宪法 A.6 或 C.5（门禁细则全文）；常用命令归 C.4；仅**所有**子项目共有的门禁总则（原则级 1–3 条）落定位层「跨切约定」 |
| 部署 / 容器（可选） | Docker / 编排 / 对象存储 | A.5 或附录 |

- 主题数 = 子宪法段落一一对应；子项目无对应组件则不生成该主题、省略对应段落（Part B 整体可按实际省略，Part C 必有）。
- **主题归属**：每个主题归属其组件所在的**子项目宪法**——后端族主题（语言+Web 框架、ORM+数据库、缓存+消息、架构/agent、网关）落对应后端子宪法；前端族主题（前端框架 + UI 栈）落前端子宪法；跨子项目主题（构建 + 测试 + CI 门禁、部署）只把**所有子项目共有**的门禁总则落根定位层「跨切约定」，各子项目的工具链与质量门禁**细则**全文落对应子宪法——多个子项目相同时也各自写全（宁可重复，禁止写成「共享」段落或互引另一子宪法替代成文）。派遣调研专员时在【输入】中标注归属。
- 每主题的调研范围（按优先级检索，来源必须真实可查，禁止编造）：
  1. **官方文档**（第一来源）：语言 / 框架 / 中间件的官方文档、官方迁移指南、官方 production/部署指南
  2. **厂商最佳实践**（第二来源）：技术栈所属厂商或头部厂商公开的工程实践规范——如 Vercel（Next.js）、Astral（uv/ruff）、LangChain（LangGraph）、Redis 官方、GitHub（CI 实践）、Anthropic（agent 工程实践）等
  3. **权威社区聚合**（第三来源）：框架官方推荐的 best-practice 指南与聚合页
- 检索不到的条目记 `{待调研项}` + 原因，禁止用记忆中的"常见规范"充数。

## 五、核心工作流（顺序执行）

1. **输入锁定 + 项目勘察**：按 §三 一次问齐；技术栈或子项目清单未提供时，派遣「项目勘察」subagent 扫描项目根（pyproject.toml / package.json / go.mod / Cargo.toml / lockfile / .env.example / docker-compose 等配置证据），输出：① 技术栈清单（按子项目分域）+ 配置证据路径；② **子项目清单**——根目录一层内所有带独立依赖清单的目录及各自技术栈与职责；整仓单应用时注明"唯一子项目，宪法落仓库根"。清单回报用户确认（用户已指定则跳过确认）。
2. **调研派遣**：按 §四 主题表生成调研任务清单（每题标注归属：定位层跨切 / 某子宪法），**并行派遣**（每个主题一个调研专员；平台不支持 subagent 派遣时按主题逐轮执行，每轮独立完成"检索 → 报告"闭环）。每次派遣必须含 §六 五要素。
3. **报告评审（主控）**：收齐报告后逐份检查——规范条目与来源一一对应、URL 真实可查、无编造；不合格退回对应调研专员补齐（≤2 轮，超限升级用户）。把「全局约束文件」实际章节号核对后写入头注。
4. **章节合成（主控）**：按 `references/template.md` 对应模板把调研报告提炼为**原则级条款**——只存工程原则与约束，不写实现细节；跨主题冲突以「官方文档 > 厂商实践 > 社区实践」裁决并注明；段落按实际技术栈裁剪。**先合成根定位层**（项目定位 + 一层目录地图 + 命令总览 + 强制阅读路由 + 子项目宪法索引 + 跨切约定 + 配套文件职责，≤ 定位层上限；子项目内部结构一律不展开，只标「规范见 <子项目>/AGENTS.md」）；**再逐子项目合成子宪法**（头注反指定位层与全局规范，内容只管本子项目深度）；**最后生成唯一根索引**（`<根>/CLAUDE.md`，claude 模式为 `<根>/AGENTS.md`：md 链接列全根定位层、全部子宪法与 TASK.md / CHANGELOG.md，纯索引不写规范正文）。合成后自查五项：① 各文档行数 ≤ 对应上限（超限必须砍重复/实现细节/功能设计）；② **归属与去重**——定位层只写**所有子项目共有**的总则；子项目约束（含兄弟子项目间相同的栈、门禁细则）全文写入各自子宪法，不互引共享、宁可重复；说明性内容（定位、目录地图、目录结构）不复制，定位层的子项目宪法索引全文只落「子项目宪法索引」章节一处、文档头只留路由规则句；③ **功能设计边界**——业务数据模型、图模型节点/关系清单、状态机事件、业务计算规则一律不写入，只留指向 `specs/` 的职责行（`specs/` 等引用路径以当前工作区实存探查为准，禁止凭记忆关联）；④ **归属正确**——子项目约束不串写（前端约束只在前端子宪法、后端约束只在后端子宪法），定位层无任何子项目深度约束；⑤ **入口可达**——定位层文档头含强制阅读路由（规则句 + 指向唯一索引章节）且索引与实际文件一一对应，各子宪法含 C.4 常用命令节，根索引链接与实际文件一一对应且全项目仅此一份索引。
5. **审核派遣**：指派「审核专员」subagent 对照 `references/template.md` 与 `references/example.md` 审核**全部**文档（结构完备、无编造、无实现细节、无业务功能设计细节混入、无重复全局规范正文、**引用链一致**——定位层索引的路径与职责描述和子宪法实存一一对应、子宪法头注反指定位层、根索引为纯 md 链接且路径可达、全项目仅此一份索引文件、**引用来源合规**——`specs/` 等设计文档引用均经当前工作区实存探查确认，无凭项目历史/全局记忆关联的旧文档）；不通过则主控修订后复审（≤2 轮，超限升级用户）。
6. **落盘**：`<目标项目根>/AGENTS.md`（定位层）+ 各 `<子项目>/AGENTS.md`（子宪法）+ **唯一根索引** `<目标项目根>/CLAUDE.md`；整仓单应用时仅 `<根>/AGENTS.md` + `<根>/CLAUDE.md`；claude 模式命名按 §二 整体对调。已存在 → 默认 `*.draft` 另存（各文件分别处理），用户明确要求覆盖时先备份旧文件；UTF-8 无 BOM、LF 行尾。副产物（均根级）：调研报告 `<目标项目根>/docs/agmds-research/{yyyy-MM-dd}-{主题}.md`、待回填登记表 `<目标项目根>/TASK.md`（无 TASK.md 时按模板附录内嵌子宪法）、变更记录 `<目标项目根>/CHANGELOG.md`（追加式，保留既有历史）。
7. **汇报**：文档体系概览（子项目清单、当前模式、宪法体系与根索引各文件路径与行数、定位层索引 ↔ 子宪法对照表）、调研报告路径清单、`{待调研项}` 登记、修订指引（宪法后续修订须先在 `CHANGELOG.md` 记变更记录再改正文；修订涉及定位层与子宪法时同步更新根索引、强制阅读路由与引用链）。

## 六、调研派遣五要素（每次派遣必含）

```markdown
【角色】调研专员——{主题}（每个调研主题一个，单一职责）
【输入】技术栈组件清单 + 实际版本 + 项目上下文 + 归属文档（定位层跨切 / 某子宪法）（禁止模糊指代）
【职责】检索官方文档与厂商最佳实践，产出规范候选条目；不做实现、不做取舍决策
【输出】`docs/agmds-research/{yyyy-MM-dd}-{主题}.md`（报告头标注题归属文档）：技术概况 + 规范候选表（规范条目 | 依据 | 来源 URL | 适用版本 | 取舍建议）
【完成标准】规范条目与来源一一对应、URL 真实可查、无编造；检索不可得条目标 `{待调研项}` 并注明原因
```

**并行规则**：无依赖主题的调研并行派遣；报告评审 → 合成 → 审核 → 落盘严格串行。

## 七、产出要求

- 路径：`<目标项目根>/AGENTS.md`（定位层）+ `<子项目>/AGENTS.md` ×N（子宪法）+ **唯一根索引** `<目标项目根>/CLAUDE.md`；整仓单应用时仅 `<根>/AGENTS.md` + `<根>/CLAUDE.md`；claude 模式全部命名按 §二 整体对调；副产物（根级）：调研报告 `<目标项目根>/docs/agmds-research/{date}-{topic}.md`、登记表 `<目标项目根>/TASK.md`、变更记录 `<目标项目根>/CHANGELOG.md`
- 结构：定位层与子宪法分别完整套用 `references/template.md` 对应模板，逐章填写，禁止缺章；子宪法 Part B 按技术栈实际省略；有 TASK.md / CHANGELOG.md 时附录与变更记录外置，头注「配套文件职责」指向
- **强制阅读路由**：定位层必含强制阅读路由（写任一子项目代码前必读其宪法）；逐子项目的路径与深度范围**只在「子项目宪法索引」章节描述一次**，文档头只保留路由规则句并指向索引章节，不得两处复述；根索引以 md 链接复现该路由
- **分层规则**：定位层只描述**根目录一层**目录结构与索引，子项目内部目录与深度约束禁止写入；宪法体系引用的根级目录职责必须在仓库地图写明（如 `docs/specs/` 功能设计与业务数据契约、`docs/agmds-research/` 调研报告，允许对这类非技术目录下钻一层标注职责），技术子项目内部仍一个字不展开；根级配套文件（TASK.md / CHANGELOG.md）在仓库地图与跨切约定中标注职责；跨切约定只写总则，细节归对应子宪法
- **归属与去重**：先判归属再落笔——**全局硬约束 = 所有子项目共有的约束**，才可上收定位层「跨切约定」且只写总则；**子项目约束**（如某端技术栈约束、质量门禁细则，哪怕双端内容相同）必须**全文写入各自子宪法**，禁止写成「共享」段落、禁止引用兄弟子宪法替代成文，**宁可子宪法间重复**；**说明性内容**（项目定位、仓库地图、目录结构等描述）不重复——各归其位只出现一次，子宪法不复制根地图或兄弟子宪法的说明；允许适当的冗余强调（一句话点题 + 指向权威落点），禁止大范围重复说明
- **唯一根索引**：全项目仅一份索引文件，落项目根、命名与宪法体系相反（agent 模式 = `CLAUDE.md`，claude 模式 = `AGENTS.md`）；以 md 链接列全根定位层、全部子宪法与 TASK.md / CHANGELOG.md；纯索引不写规范正文，不与宪法体系重复任何内容；**禁止在各子项目目录生成索引文件**——根索引经链接间接可达全部宪法
- 内容：只存工程原则与约束，每条可验证；语言：中文；编码 UTF-8 无 BOM、LF 行尾；各文档正文 ≤ 对应行数上限（定位层 200 / 子宪法 500 默认）；无大范围重复说明（边界见「归属与去重」条）
- **功能设计边界**：业务数据模型、图模型节点/关系清单、状态机事件、业务计算规则等**一律禁止写入**，只留指向 `specs/` 的职责行
- **变更记录外置**：宪法正文不设变更控制/变更记录章节，修订流程 = 先记 `CHANGELOG.md` 再改正文，语义由头注「配套文件职责」承载
- 占位符：`{待调研项}` 集中于 TASK.md「待回填登记表」（无 TASK.md 时内嵌子宪法附录）登记并汇报，禁止编造
- 引用不重复：全局约束文件已有段落只引用（含章节号）不复制正文；定位层与子宪法之间引用链互通但不重复正文；兄弟子宪法之间不互引替代成文（约束各自写全）
- **引用来源合规**：`specs/` 等设计文档与一切项目材料引用只能来自用户本次输入或当前工作区实存探查；禁止基于项目历史记忆、全局记忆、历史会话关联旧 / 临时设计文档——宁可不留引用（登记 `{待调研项}`），不可凭记忆建链污染宪法

## 八、反模式（禁止）

- ❌ 编造厂商规范或来源 URL → 每条规范必须真实可溯源（调研报告）
- ❌ 主控亲自调研 → 调研一律派遣 subagent（§五.2），主控只编排与合成
- ❌ 重复全局 AGENTS.md 已有规范正文 → 引用不重复
- ❌ 子项目内部结构 / 深度约束写进根定位层 → 定位层只做一层目录地图 + 索引 + 跨切总则（§七分层规则）
- ❌ 定位层缺强制阅读路由、路由与宪法索引不一致、或文档头与索引章节两处复述子项目宪法索引 → 路由规则句必含，索引全文只在「子项目宪法索引」章节描述一次（§七强制阅读路由）
- ❌ 子项目约束写成「共享」——双端共享栈、质量门禁细则等不各自全文落款，而是共享段落或互引兄弟子宪法替代 → 必须全文写入各自子宪法，宁可重复；仅**所有**子项目共有的总则上收定位层（§七归属与去重）
- ❌ 兄弟子宪法大范围复制说明性内容（根目录地图、项目定位、彼此的目录结构）→ 说明性内容各归其位只出现一次，允许一句话冗余强调（§七归属与去重）
- ❌ 子宪法缺「常用命令」节 → Part C 必含打包 / 测试 / 格式化 / 修复 / 启动等命令（模板二 C.4）
- ❌ 仓库地图缺 docs/specs/ 等宪法关联目录的职责说明 → 宪法引用的根级目录职责必须在定位层写明，可下钻一层标注（§七分层规则）
- ❌ 根索引缺失、未用 md 链接语法、链接路径失效或写了规范正文 → §七「唯一根索引」规则，审核专项核对（§五.5）
- ❌ 在子项目目录生成索引文件（旧版「每份宪法同目录配一份索引」）→ 全项目唯一根索引，经链接间接可达全部宪法（§二）
- ❌ claude / agent 模式命名混用（宪法体系内一半 AGENTS.md 一半 CLAUDE.md）→ 体系命名随子命令整体切换（§二）
- ❌ 前端约束写进后端子宪法（或反之）→ 约束归属其子项目宪法（§五.4 自查④）
- ❌ 定位层索引与子宪法实际路径 / 职责描述不一致 → 审核派遣专项核对（§五.5）
- ❌ 定位层与子宪法重复同一规则正文、或说明性内容大范围复制 → 总则归定位层、细则与全文归子宪法，说明各归其位（§七归属与去重）
- ❌ 业务功能设计写入宪法（业务数据模型、图模型节点/关系清单、状态机事件、业务规则） → 归 `specs/`，宪法只留职责引用行（§五.4 自查③）
- ❌ 基于项目历史记忆 / 全局记忆 / 历史会话关联设计文档（凭记忆写 `specs/` 引用、指向临时或已废弃的旧文档）→ 引用只认当前工作区实存，实存缺失就不引用并登记 `{待调研项}`（§三引用来源红线、§七引用来源合规）
- ❌ 宪法正文设「变更控制 / 变更记录」章节 → 变更记录一律外置 `CHANGELOG.md`，头注指向即可（§七）
- ❌ 写入实现细节 → "怎么实现"留给代码与 TASK.md
- ❌ 正文超行数上限或同一规则重复描述 → §五.4 合成自查强制拦截，超限必须精简
- ❌ 无技术栈依据凭空写约束 → 版本与规范必须来自用户提供或勘察证据
- ❌ 目标已存在同名产物不确认直接覆盖 → 默认另存 draft
- ❌ 产物仅存于对话不落盘
- ❌ TASK.md / CHANGELOG.md 外置后头注「配套文件职责」缺失或与实际文件不一致 → 文件职责一一对应（§七）
