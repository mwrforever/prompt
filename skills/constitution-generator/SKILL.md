# 项目宪法生成器（AGENTS.md / CLAUDE.md 双入口）

> 按项目技术栈派发 subagent 调研官方文档与厂商最佳实践，依 `references/template.md` 的**宪法基础框架**组装分层宪法体系，只存工程原则与约束（业务设计归 `specs/`，变更记录归 `CHANGELOG.md`，登记归 `TASK.md`）。主控只编排（输入锁定、CI 确认、派遣、评审、合成、审核、落盘），调研与审核一律派遣 subagent。

## 一、文档体系

| 产物 | 职责 | 行数上限 |
|---|---|---|
| 根定位层 `<根>/{AGENTS.md\|CLAUDE.md}` | 项目定位、一层目录地图、命令总览、强制阅读路由、子项目宪法索引、约束效力与遵从总则、跨切约定（含 CI 链总则）、「配套文件职责」唯一声明 | 200 |
| 子项目宪法 `<子项目>/{AGENTS.md\|CLAUDE.md}` ×N | 本子项目全部宪法深度：Part A 技术栈通用（含 A.7 跨层数据对象与传参约束）、Part B 架构分层、Part C 实际（C.4 常用命令、C.5 CI 生产落地方案必含） | 500 |
| 根索引 `<根>/{CLAUDE.md\|AGENTS.md}` | 纯 md 链接列全定位层、全部子宪法与配套文件，不写规范正文 | — |

- **双入口同时生成**：两种命名必然同时产出——用户选定的命名承载**宪法实体**，相反命名只做**根索引**。agent 模式（默认）= AGENTS.md 实体 + `CLAUDE.md` 根索引；claude 模式整体对调。两模式流程全同，仅命名对调，禁止体系内混用。
- **索引只落根目录一份**：根索引经链接可达全部宪法；禁止在子项目目录生成任何索引文件，子宪法不重复承载索引。
- **整仓单应用**（依赖清单位于仓库根、无并列技术子目录）：只产出一份子宪法落仓库根（定位与深度合一，约束效力总则与配套文件职责由其承载），根索引照常生成。

## 二、子命令路由

`/constitution-generator [claude|agent] {用户指令}`；首个 token 非 `claude|agent` 时整段视为指令，走默认 agent 模式。

## 三、输入收集（一次问齐）

| 输入 | 规则 | 缺省 |
|---|---|---|
| 项目名与定位 | 一句话业务描述 | 工作区目录名 |
| 技术栈清单 | 按子项目分域；版本只认用户输入或勘察到的配置证据，禁编造 | 缺失则派勘察 subagent 推断 |
| 子项目清单 | 根目录一层内带独立依赖清单（pyproject.toml / package.json / go.mod 等）的目录及职责；非技术目录不入宪法体系 | 勘察判定 |
| **CI 链现状与需求** | 勘察探测既有 CI（`.github/workflows/`、`.gitlab-ci.yml`、`Jenkinsfile` 等）：有则沿用、只调研补强；**无 CI 或技术栈未定**时先问清 ①服务清单（是否「用户端 + 管理端」多前端）②基础技术栈 ③期望 CI 形态（工具 / 阶段 / 门禁 / 部署），派 CI 调研专员出 2–3 套方案供用户选定 | 勘察探测 |
| 全局约束文件 | 只引用其注释 / 日志 / 测试规范章节，不复制正文；章节号先读后写，定位层与子宪法同源同章节 | 探测常见位置，无则不引用 |
| 项目特有材料 | `specs/` 等设计文档只引用路径与职责；**只认当前工作区实存**，禁凭历史 / 全局记忆关联，实存缺失就登记 `{待调研项}` | 无 |
| 登记 / 变更文件 | `TASK.md`（登记台）+ `CHANGELOG.md`（变更记录，先记再改），均根级共用；「配套文件职责」声明只落定位层头注，子宪法只留指向不复述 | 无则新建 |
| 行数上限 | 超限必须砍重复、实现细节、功能设计 | 200 / 500 |
| 修订模式 | 目标文件已存在 → 另存 `*.draft`；用户要求覆盖时先备份旧文件 | draft |

- **CI 先行**：CI 链方案经用户选定前，禁止派遣其它主题调研、禁止定稿其它章节。

## 四、调研主题（强耦合合并，不过度拆分）

| 主题 | 覆盖组件 | 框架槽位 |
|---|---|---|
| **CI 链 / 生产落地**（最先派遣，方案先经用户确认） | 如 GitHub Actions / GitLab CI / Jenkins | 定位层跨切·CI 链总则 + 各子宪法 C.5 |
| 语言 + Web 框架 | 如 Python 3.12 + FastAPI | A.1 / A.3 / A.7 本栈习语 |
| ORM + 迁移 + 数据库 | 如 SQLAlchemy + Alembic + PostgreSQL | A.4 |
| 缓存 + 消息队列 | 如 Redis + Stream | A.5 |
| 架构 / agent 框架 | 如 LangGraph | Part B |
| LLM / 媒体网关 | 如 litellm | B.4 |
| 前端框架 + UI 栈 | 如 Next.js + TS + Tailwind | 前端子宪法 A.1 / Part B / A.7 本栈习语 |
| 构建 + 测试 | 如 uv / ruff / pytest / pre-commit | C.4 / C.6；共有门禁总则落定位层 |
| 部署 / 容器（可选） | Docker / 编排 / 对象存储 | A.5 或附录 |

- 每主题归属其组件所在子项目；无对应组件则整段省略（Part B 可整体省略），省略时编号不重排。
- **内置条款不依赖调研**：定位层约束效力总则、各子宪法 A.7 三原则与例外边界、C.4 / C.5 骨架按模板直写；调研只补本栈习语（对象建模术语、命令清单）与流水线细则。
- 来源优先级：官方文档 > 厂商最佳实践 > 权威社区聚合；检索不到记 `{待调研项}` 并注明原因，禁用记忆充数。

## 五、工作流

1. **勘察 + CI 确认**：扫描配置证据，输出技术栈清单（分域 + 证据路径）、子项目清单、CI 现状，回报用户确认（已指定则跳过）。无既有 CI 或技术栈未定时按 §三问清，派 CI 调研专员出方案，**用户选定后**才进入下一步。
2. **调研派遣**：其余主题并行派遣（每主题一个 subagent；平台不支持派遣时逐主题串行完成"检索 → 报告"闭环），每次含 §六五要素。
3. **报告评审**：按派单槽位核对覆盖度；条目与来源一一对应、URL 真实可查；不合格退回补齐（≤2 轮，超限升级用户）。
4. **章节合成**：按 template.md 逐槽提炼为原则级条款（冲突按来源优先级裁决并注明）；顺序：根定位层 → 各子宪法 → 根索引。合成后自查六项：① 行数达标；② 归属与去重——共有总则归定位层、子项目约束各自成文宁可重复、说明性内容与「配套文件职责」不复制；③ 业务设计不写入（归 `specs/` 职责行）；④ 约束不串写（前端约束不进后端子宪法，子项目深度约束不进定位层）；⑤ 路由与索引可达——强制阅读路由在位、根索引链接与实存一一对应；⑥ 框架完备——必含章节齐全、A.7 按栈翻译、C.5 与选定方案一致。
5. **审核派遣**：审核专员对照 template / example 审全部文档：结构完备、内置条款齐备、无编造、无实现细节、引用链一致（定位层索引 ↔ 子宪法实存、子宪法头注反指定位层、根索引纯链接可达）、CI 落地一致、引用实存合规；不通过主控修订复审（≤2 轮，超限升级用户）。
6. **落盘**：宪法体系 + 根索引；已存在按修订模式处理；UTF-8 无 BOM、LF 行尾。副产物（根级）：调研报告 `docs/agmds-research/{yyyy-MM-dd}-{主题}.md`、`TASK.md`、`CHANGELOG.md`（追加式保留既有历史）。
7. **汇报**：体系概览（文件路径与行数、索引对照表、CI 方案及选定记录）、调研报告清单、`{待调研项}` 登记、修订指引（先记 CHANGELOG 再改正文；修订时同步更新根索引与阅读路由）。

## 六、调研派遣五要素

```markdown
【角色】调研专员——{主题}（单一职责）
【输入】技术栈 + 实际版本 + 项目上下文 + 归属文档 + 目标框架槽位与必备约束方向（禁模糊指代）
【职责】检索官方文档与厂商最佳实践，按槽位产出规范候选条目；不做实现、不做取舍
【输出】`docs/agmds-research/{yyyy-MM-dd}-{主题}.md`（报告头标注归属与槽位，正文按槽位分节）：技术概况 + 规范候选表（条目 | 依据 | 来源 URL | 适用版本 | 取舍建议）
【完成标准】标注槽位逐节有候选覆盖（不可得记 `{待调研项}` 并注明原因）；条目与来源一一对应、URL 真实可查、无编造
```

## 七、反模式

- ❌ 缺任一命名（实体或根索引只出一方）；子项目目录生成索引；claude / agent 命名混用
- ❌ 编造规范或来源 URL；主控亲自调研；产物仅存对话不落盘
- ❌ 子项目内部结构 / 深度约束写进定位层；前端约束写进后端子宪法（或反之）
- ❌ 定位层缺强制阅读路由或约束效力总则；子宪法缺 A.7 / C.4 / C.5；A.7 照抄抽象表述不按栈翻译
- ❌ 子项目约束写成「共享」段落或互引兄弟子宪法替代；同一规则在定位层与子宪法重复成文
- ❌ 业务功能设计（数据模型 / 状态机 / 业务规则）写入宪法；`specs/` 引用凭历史 / 全局记忆关联
- ❌ 子宪法复述「配套文件职责」清单；宪法正文设变更控制章节；复制全局规范正文（引用含章节号不算）
- ❌ CI 方案未确认就调研定稿其它章节；C.5 与选定方案不一致
- ❌ 写实现细节；超行数上限；无技术栈依据凭空写约束；目标已存在不确认直接覆盖
