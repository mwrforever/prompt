# 项目宪法生成器（AGENTS.md / CLAUDE.md 双入口）

> 优先复用技能内置**本地宪法库**（`data/stack/{技术栈}.md` 技术栈宪法 + `data/ci/{语言}.md` CI 构建配置段，规范见 §五），未命中的主题才派发 subagent 调研官方文档与厂商最佳实践；用户明确确认达标后将新调研片段回写补库。依 `references/template.md` 的**宪法基础框架**组装分层宪法体系，只存工程原则与约束、零功能实现描述（功能说明归 `specs/`，变更记录归 `CHANGELOG.md`，登记归 `TASK.md`）。主控只编排（输入锁定、CI 确认、查库、派遣、评审、合成、审核、落盘、达标回写），调研与审核一律派遣 subagent。

## 一、文档体系

| 产物 | 职责 | 行数上限 |
|---|---|---|
| 根定位层 `<根>/{AGENTS.md\|CLAUDE.md}` | 项目定位、一层目录地图、命令总览、强制阅读路由、子项目宪法索引、约束效力与遵从总则、跨切约定（含 CI 链总则）、「配套文件职责」唯一声明 | 200 |
| 子项目宪法 `<子项目>/{AGENTS.md\|CLAUDE.md}` ×N | 本子项目全部宪法深度：Part A 技术栈通用（含 A.7 跨层数据对象与传参约束；前端另含 A.8 UI 设计四段律（凡涉 UI 任何变更无论大小一律强制全流程，主 agent 只编排派遣、UI 设计实现与验证一律 subagent 承担，逐段先实际加载对应插件技能、禁空思考，验段按问题定级打回））、Part B 架构分层、Part C 实际（C.4 常用命令、C.5 CI 生产落地方案必含） | 500 |
| 根索引 `<根>/{CLAUDE.md\|AGENTS.md}` | 纯 md 链接列全定位层、全部子宪法与配套文件，不写规范正文 | — |

- **双入口同时生成**：两种命名必然同时产出——用户选定的命名承载**宪法实体**，相反命名只做**根索引**。agent 模式（默认）= AGENTS.md 实体 + `CLAUDE.md` 根索引；claude 模式整体对调。两模式流程全同，仅命名对调，禁止体系内混用。
- **索引只落根目录一份**：根索引经链接可达全部宪法；禁止在子项目目录生成任何索引文件，子宪法不重复承载索引。
- **整仓单应用**（依赖清单位于仓库根、无并列技术子目录）：只产出一份子宪法落仓库根（定位与深度合一，约束效力总则与配套文件职责由其承载），根索引照常生成。

## 二、触发与子命令路由（仅限显式调用）

- **触发（仅限显式调用）**：用户显式调用 `/constitution-generator [claude|agent] {用户指令}` 是唯一触发方式；「根据技术栈生成项目宪法 / 项目规范 / AGENTS.md / CLAUDE.md / 项目规范文件」「派发 subagent 调研厂商最佳实践」「编码约束 / API 规范 / 层级依赖 / 变更控制 / CI 门禁」「前后端规范分开 / monorepo 各模块一份规范」等需求描述或关键词不构成触发条件，不得据此推断触发、主动调用或推荐本技能。
- **加载**：触发后必须先读本 SKILL.md 与 `references/template.md`（`references/example.md` 作风格参照），严格按流程执行；禁止跳过技能内容、仅凭对话印象直接生成宪法。
- **子命令路由**：`/constitution-generator [claude|agent] {用户指令}`；首个 token 非 `claude|agent` 时整段视为指令，走默认 agent 模式。

## 三、输入收集（一次问齐）

| 输入 | 规则 | 缺省 |
|---|---|---|
| 项目名与定位 | 一句话业务描述 | 工作区目录名 |
| 技术栈清单 | 按子项目分域；版本只认用户输入或勘察到的配置证据，禁编造 | 缺失则派勘察 subagent 推断 |
| 子项目清单 | 根目录一层内带独立依赖清单（pyproject.toml / package.json / go.mod 等）的目录及职责；非技术目录不入宪法体系 | 勘察判定 |
| **CI 链现状与需求** | 勘察探测既有 CI（`.github/workflows/`、`.gitlab-ci.yml`、`Jenkinsfile` 等）：有则沿用、只调研补强；**无 CI 或技术栈未定**时先问清 ①服务清单（是否「用户端 + 管理端」多前端）②基础技术栈 ③期望 CI 形态（工具 / 阶段 / 门禁 / 部署）；技术栈已定且 `data/ci/{语言}.md` 命中时优先由库内 CI 构建配置段组装方案，库未覆盖或需对比才派 CI 调研专员出 2–3 套方案供用户选定 | 勘察探测 |
| 全局约束文件 | 只引用其注释 / 日志 / 测试规范章节，不复制正文；章节号先读后写，定位层与子宪法同源同章节 | 探测常见位置，无则不引用 |
| 项目特有材料 | `specs/` 等设计文档只引用路径与职责；**只认当前工作区实存**，禁凭历史 / 全局记忆关联，实存缺失就登记 `{待调研项}` | 无 |
| 登记 / 变更文件 | `TASK.md`（登记台）+ `CHANGELOG.md`（变更记录，先记再改），均根级共用；「配套文件职责」声明只落定位层头注，子宪法只留指向不复述 | 无则新建 |
| 行数上限 | 超限必须砍重复、实现细节、功能设计 | 200 / 500 |
| 修订模式 | 目标文件已存在 → 另存 `*.draft`；用户要求覆盖时先备份旧文件 | draft |

- **CI 先行**：CI 链方案经用户选定前，禁止派遣其它主题调研、禁止定稿其它章节。

## 四、调研主题（强耦合合并，不过度拆分）

| 主题 | 覆盖组件 | 框架槽位 |
|---|---|---|
| **CI 链 / 生产落地**（最先处理：查 `data/ci/{语言}.md`，未命中才派遣；方案先经用户确认） | 如 GitHub Actions / GitLab CI / Jenkins | 定位层跨切·CI 链总则 + 各子宪法 C.5 |
| 语言 + Web 框架 | 如 Python 3.12 + FastAPI | A.1 / A.3 / A.7 本栈习语 |
| ORM + 迁移 + 数据库 | 如 SQLAlchemy + Alembic + PostgreSQL | A.4 |
| 缓存 + 消息队列 | 如 Redis + Stream | A.5 |
| 架构 / agent 框架 | 如 LangGraph | Part B |
| LLM / 媒体网关 | 如 litellm | B.4 |
| 前端框架 + UI 栈 | 如 Next.js + TS + Tailwind | 前端子宪法 A.1 / Part B / A.7 本栈习语 |
| 构建 + 测试 | 如 uv / ruff / pytest / pre-commit | C.4 / C.6；共有门禁总则落定位层 |
| 部署 / 容器（可选） | Docker / 编排 / 对象存储 | A.5 或附录 |

- **本地宪法库优先（未命中才派遣）**：每主题派遣前先查本地宪法库——栈主题查 `data/stack/{技术栈}.md`、CI 段查 `data/ci/{语言}.md`（命中判定见 §五）——全命中直接复用不派遣、部分命中仅对缺失槽位派遣补齐、全未命中整主题派遣；命中条目按槽位进入章节合成，效力等同调研报告。
- 每主题归属其组件所在子项目；无对应组件则整段省略（Part B 可整体省略），省略时编号不重排。
- **内置条款不依赖调研**：定位层约束效力与遵从总则（含主控触达 / subagent 派遣强制加载对应子宪法纪律）、各子宪法 A.7 三原则与例外边界、前端子宪法 A.8 谋建琢验四段律（凡涉 UI 任何变更无论大小一律强制全流程，主编排 · 子实现 · 页为单位验证，逐段强制加载对应技能禁空思考，验段按问题定级打回，按模板原文直写）、C.4 / C.5 骨架按模板直写；调研只补本栈习语（对象建模术语、命令清单）与流水线细则。
- 来源优先级：官方文档 > 厂商最佳实践 > 权威社区聚合；检索不到记 `{待调研项}` 并注明原因，禁用记忆充数。

## 五、本地宪法库（data/ · 查库优先，未命中才派遣）

技能包 `data/` 目录内置技术宪法库，双目录布局：技术栈宪法存 `data/stack/{技术栈}.md`（小写 kebab-case，主语言 / 运行时在前、框架在后，如 `python-fastapi.md`、`typescript-nextjs.md`；独立基础设施主题单独成文件，如 `redis-stream.md`），CI 构建配置段存 `data/ci/{语言}.md`（按语言唯一命名，如 `python.md`、`typescript.md`；同语言多框架差异以条目内小节区分）。库文件以本技能基准目录为根解析相对路径；条目格式与索引见 `data/README.md`。库初始为空，条目仅经 §六.9 达标回写增长。

- **命中判定**（§六.2 查库时逐主题执行，三条全满足才算该槽位命中）：
  1. 对应库文件存在（`data/stack/{技术栈}.md` 或 `data/ci/{语言}.md`）；
  2. 文件头「适用范围」覆盖项目实测版本（低于版本下限视为未命中）；
  3. 该主题所需槽位 / 平台在文件中有对应分节（如 ORM 主题查 A.4 分节、CI 主题查目标平台分节）。
  全部命中 → 直接复用、不派遣；部分槽位缺失 → 仅缺失槽位派遣补齐；文件不存在 → 整主题派遣。
- **复用纪律**：命中条目按槽位进入章节合成，效力等同调研报告（来源记库条目文件）；合成时仍须按项目实测事实裁剪（版本、命令、目录名、包管理器），禁整段照抄与项目无关条款；A.7 三原则、A.8 四段律等体系内置条款仍按 template 直写，不因库命中而省略。
- **达标回写（唯一入库路径）**：仅当用户**明确表示**宪法达标（「达标 / 通过 / 可以」等明确认可；模糊回应、沉默、会话结束均不算）后，把本次「未命中 → 派遣调研 → 合成」所得片段回写：栈宪法片段回写 `data/stack/{技术栈}.md`（新栈新建文件、部分命中的并入既有文件补缺失分节），CI 片段回写 `data/ci/{语言}.md`（新语言新建、既有的并入补缺失平台 / 框架分节）；内容为通用条款——剥离项目专属细节（目录名、业务模型、端口、项目名）；文件头登记入库日期、适用范围与「经用户达标确认」标记；同步更新 `data/README.md` 索引。禁回写用户未确认、含 `{待调研项}` 或凭记忆推测的内容。
- **只读兜底**：技能基准目录不可写（如插件缓存只读挂载）时禁静默丢弃——将回写片段全文与目标路径汇报用户，请在技能源仓库完成入库；插件缓存目录可写时回写有效但会被插件更新覆盖，须提示用户同步至技能源仓库。

## 六、工作流

1. **勘察 + CI 确认**：扫描配置证据，输出技术栈清单（分域 + 证据路径）、子项目清单、CI 现状，回报用户确认（已指定则跳过）。无既有 CI 或技术栈未定时按 §三问清（技术栈已定且 `data/ci/{语言}.md` 命中时优先由库内 CI 段组装方案，库未覆盖才派 CI 调研专员），方案**用户选定后**才进入下一步。
2. **本地宪法库查询**：按 §四主题清单逐项查库（命中判定 §五）——栈主题查 `data/stack/{技术栈}.md`、CI 段查 `data/ci/{语言}.md`，登记命中槽位复用清单与未命中派遣清单，回报用户本次「直接复用 / 派遣调研」分工；库目录不可读时按全未命中处理。
3. **调研派遣**：仅对未命中主题 / 槽位并行派遣（每主题一个 subagent；平台不支持派遣时逐主题串行完成"检索 → 报告"闭环），每次含 §七五要素。
4. **报告评审**：按派单槽位核对覆盖度；条目与来源一一对应、URL 真实可查；不合格退回补齐（≤2 轮，超限升级用户）。
5. **章节合成**：按 template.md 逐槽提炼为原则级条款（来源 = 本地库命中条目 + 调研报告，冲突按来源优先级裁决并注明——库条目与调研报告同级，取来源更权威或更新近者）；顺序：根定位层 → 各子宪法 → 根索引。合成后自查六项：① 行数达标；② 归属与去重——共有总则归定位层、子项目约束各自成文宁可重复、说明性内容与「配套文件职责」不复制；③ 零功能实现描述——全篇仅约束表述（禁令 / 必须 / 边界），凡系统做什么 / 怎么实现（功能清单、流程步骤、模块机制）一律删除归 `specs/`；④ 约束不串写（前端约束不进后端子宪法，子项目深度约束不进定位层）；⑤ 路由与索引可达——强制阅读路由与「主控触达 / subagent 派遣先实际加载对应子宪法」纪律在位、根索引链接与实存一一对应；⑥ 框架完备——必含章节齐全、A.7 按栈翻译、前端 A.8 四段律含执行模式铁律按模板直写在位、C.5 与选定方案一致、命令与目录层级按 template 以代码块 / 文本块呈现。
6. **审核派遣**：审核专员对照 template / example 审全部文档：结构完备、内置条款齐备、无编造（本地库条目与调研报告双来源核对）、零功能实现描述与实现细节、引用链一致（定位层索引 ↔ 子宪法实存、子宪法头注反指定位层、根索引纯链接可达）、CI 落地一致、引用实存合规；不通过主控修订复审（≤2 轮，超限升级用户）。
7. **落盘**：宪法体系 + 根索引；已存在按修订模式处理；UTF-8 无 BOM、LF 行尾。副产物（根级）：调研报告 `docs/agmds-research/{yyyy-MM-dd}-{主题}.md`、`TASK.md`、`CHANGELOG.md`（追加式保留既有历史）。
8. **汇报**：体系概览（文件路径与行数、索引对照表、CI 方案及选定记录）、调研报告清单、本地库复用与派遣分工回顾、`{待调研项}` 登记、修订指引（先记 CHANGELOG 再改正文；修订时同步更新根索引与阅读路由）；并明确告知——本次派遣调研所得技术栈片段经用户明确表示达标后将回写本地宪法库（§五）。
9. **达标回写（条件执行）**：仅当用户明确表示宪法达标后执行——按 §五回写规则把本次新调研且经用户确认的片段写入 `data/stack/{技术栈}.md` 与 `data/ci/{语言}.md`（新条目新建文件、缺失分节并入补齐），并同步更新 `data/README.md` 索引；未获明确确认不得回写，会话结束未确认视为放弃。

## 七、调研派遣五要素

```markdown
【角色】调研专员——{主题}（单一职责）
【输入】技术栈 + 实际版本 + 项目上下文 + 归属文档 + 目标框架槽位与必备约束方向（禁模糊指代）
【职责】检索官方文档与厂商最佳实践，按槽位产出规范候选条目；不做实现、不做取舍
【输出】`docs/agmds-research/{yyyy-MM-dd}-{主题}.md`（报告头标注归属与槽位，正文按槽位分节）：技术概况 + 规范候选表（条目 | 依据 | 来源 URL | 适用版本 | 取舍建议）；候选条目须栈 / 语言级通用可复用——本报告同时作为达标回写本地宪法库（stack / ci）的候选（§五）
【完成标准】标注槽位逐节有候选覆盖（不可得记 `{待调研项}` 并注明原因）；条目与来源一一对应、URL 真实可查、无编造
```

## 八、反模式

- ❌ 未显式调用即凭需求描述或关键词（「生成项目宪法 / 项目规范」等）推断或主动触发本技能 → 仅显式调用 `/constitution-generator` 触发（第二节）
- ❌ 缺任一命名（实体或根索引只出一方）；子项目目录生成索引；claude / agent 命名混用
- ❌ 编造规范或来源 URL；主控亲自调研；产物仅存对话不落盘
- ❌ 本地宪法库已命中仍派遣调研（重复劳动）；命中条目不按项目实测裁剪、整段照抄与项目无关条款
