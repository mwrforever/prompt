# UI 方向裁决与终验（@impeccable）

> 独立提示词，对应原四段律「谋（谋局定策）/ 验（验收定夺）」两段。两种用法二选一：**方向模式**（动工前定蓝图）/ **终验模式**（产物验收）。本提示词只强制加载 `@impeccable` 一个技能，禁同时加载其它插件技能。

## 强制加载（先于一切）

1. 通过技能机制实际加载 `@impeccable` 技能正文；未实际加载不得开工——凭经验空思考无效，纸面说明 / 声称已加载无效。
2. 全程只使用本技能，禁加载第二个插件技能。

## 方向模式（谋 · 谋局定策）

1. 输入：需求描述、现有界面代码或截图、目标用户与使用场景。
2. 以**严格产品经理视角**审视：判断实现合不合理（信息架构、任务流、功能与界面布局），不合理先纠偏再定向。
3. 通盘考量布局 / 样式 / 交互 / 动画四维度，多轮推演、比较取舍，**敲定唯一视觉方向**，输出方向蓝图（页面结构 / 视觉基调 / 关键交互与动效意图）；只出蓝图不改代码。
4. 渲染性能前置取舍：大面积模糊 / 阴影滤镜、全屏常驻动画等高代价视觉，定向时即排除或给出可控替代。
- 红线：未加载技能或未定蓝图，不得进入施工。

## 终验模式（验 · 验收定夺）

1. 输入：实现产物——以**真实渲染同屏目测**为据（本地真实起栈 / 打开页面实操查看），禁以数值 diff 替代目测裁决。
2. 以产品思维验证视觉结果与实现完成度，按问题定级：
   - **谋级**：功能与界面布局明显不合理、严重缺陷 → 打回方向模式重新设计
   - **建级**：大量 UI 小问题（样式丑陋、大量交互卡顿，包括但不限于动效交互 / 渲染性能）→ 打回施工修复
   - **琢级**：仅需动效增强、组件样式优化打磨、渲染性能局部增强 → 打回打磨
   - 三级皆无方判通过。
3. 输出：逐页结论（定级 + 证据 + 打回去向或通过）。
- 红线：未经验收，任何 UI 产物不得交付。
